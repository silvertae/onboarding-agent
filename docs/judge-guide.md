# 심사위원 안내

온보딩 에이전트는 회사 계정을 발급받은 뒤의 신입 온보딩을 신입·교육 담당자·경영지원·관리자가 함께 처리하는 웹 서비스입니다. 화면 브랜딩은 회사 CI(Blueward)를 쓰지만, **사람·계정·과제·지식은 모두 가상 데이터**입니다.

## 접속

| 항목 | 값 |
|---|---|
| 주소 | `https://<운영 Hosting 사이트>.web.app` *(운영 배포 후 기입)* |
| 운영 기간 | 공개 후 한 달 *(시작일·종료일 기입)* |
| 권장 환경 | PC 크롬·엣지 최신 버전. 신입 화면만 모바일 폭을 지원합니다 |

로그인은 메일과 비밀번호로 합니다. 공개 가입 기능은 없습니다.

## 역할별 계정

비밀번호는 이 문서에 적지 않고 **별도로 전달**합니다.

| 역할 | 메일 | 처음 열리는 화면 |
|---|---|---|
| 관리자 | `admin@demo.test` *(운영 설정이 다르면 그 값으로 기입)* | 사용자 관리 |
| 신입 | `newhire@demo.test` | 내 온보딩(타임라인) |
| 교육 담당자(AI팀) | `trainer@demo.test` | 팀 신입 현황 |
| 경영지원 · 인사 | `hr@demo.test` | 부서 업무함 |
| 경영지원 · 총무 | `ga@demo.test` | 부서 업무함 |
| 경영지원 · 회계 | `acc@demo.test` | 부서 업무함 |

기본 계정은 여러 심사위원이 함께 씁니다. 다른 분의 진행 결과와 섞이지 않게 하려면 관리자에게 심사위원별 신입 계정을 요청해 주세요. 관리자는 "사용자 관리"에서 바로 만들 수 있고, 새 신입 계정에는 온보딩 과제 31개가 미리 준비됩니다(교육 담당자가 과제를 추가했다면 그 과제까지 들어갑니다).

## 5분 체험 순서

브라우저 창 두 개(하나는 시크릿 창)를 열면 신입과 담당자 화면을 나란히 볼 수 있습니다.

1. **신입**(창 1): 로그인해 입사일·첫 주·첫 달 타임라인을 봅니다. "명함 신청" 과제에서 영문 이름을 넣고 제출합니다.
2. **총무**(창 2): 부서 업무함에서 명함 신청을 확인합니다. 창 1의 신입 화면이 새로고침 없이 "완료"로 바뀝니다.
3. **신입**(창 1): 오른쪽 채팅에 "노트북 경비 계정과목이 뭐야?"를 물어보면 등록된 지식으로 답합니다. "동호회 가입비 얼마야?"처럼 등록되지 않은 질문에는 지어내지 않고 "확인되지 않은 내용이에요."라고 답하며, 답변 아래 "담당자에게 등록 요청"을 누른 질문만 담당자에게 갑니다.
4. **교육 담당자**(창 2): "지식 관리"의 미답변 질문(신입이 "담당자에게 등록 요청"으로 보낸 것)에 답을 등록합니다. 신입이 같은 질문을 다시 하면 이제 답합니다.
5. **교육 담당자**(창 2): "시험 출제"에서 주제와 난이도를 넣고 먼저 "문제은행에서 채우기"를 누릅니다. 팀 문제은행에 맞는 문항이 있으면 그것부터 붙고, 모자란 만큼만 "초안 만들기"(문항이 있으면 "부족분 AI로 만들기")로 문제·모범 답안·채점 기준 초안을 받습니다. 고친 뒤 "확정"하면 새 문항이 문제은행에 쌓이고, 시험지·답안지를 인쇄 화면으로 확인합니다.
6. **교육 담당자**(창 2): 신입 상세의 평가 칸 "응시 시험"에서 확정한 시험을 연결합니다. 같은 주제로 두 번째 시험을 만들면 은행 문항이 먼저 채워지고 AI는 부족분만 만듭니다. 참고할 신입으로 그 신입을 고르면 이미 본 문항은 빠집니다. "문제은행" 메뉴에서는 문항을 고치거나 숨기고, 직접 추가할 수 있습니다.
7. **교육 담당자**(창 2): 메뉴 "온보딩 과제"에서 "과제 추가"로 새 과제를 만들고, 그 과제에 서식(docx·xlsx·pdf, 가상 내용만)을 올립니다. 진행 중인 신입이 있는 과제는 제목·안내문만 고칠 수 있다는 안내가 나옵니다. 관리자 계정으로 신입을 등록하거나 관리자에게 요청해 새 신입 계정을 받으면 그 신입 타임라인에 새 과제와 "서식 1"이 보이고, 과제 상세의 "내려받기"로 원본 이름의 파일을 받습니다. 신입 상세의 "이 신입에게 과제 추가"는 그 신입에게만 들어가고 다른 신입 화면에는 없습니다. 회계 담당자로 `AC-01`을 열면 기본 서식 2개가 보입니다(지우기 버튼 없음).
8. **경영지원**(창 2, 인사): 메뉴 "규정 문서"에서 "문서 올리기"로 저장소의 `supabase/seed-docs/welfare-policy.docx`를 올립니다(문서 이름 "복리후생 규정(가상)"). 처리가 끝나면 상태가 "사용 중"이 되고 조항 목록이 보입니다.
9. **경영지원**(창 2): 같은 화면에서 "지식 초안 만들기"를 누르고 "지식 관리에서 검토하기"로 이동해, "AI 작성" 배지가 붙은 초안을 확인하고 "게시"합니다. AI는 게시하지 못하고 게시하기 전에는 신입에게 보이지 않습니다.
10. **신입**(창 1): 채팅에 "결혼하면 경조금 얼마 받아?"를 물으면 규정 조항에 근거해 답하고, 답변 아래 "규정 원문" 칩을 누르면 조항 원문이 열립니다.
11. **교육 담당자**(창 2): "지식 관리"의 미답변 질문에서 "규정에서 답 초안 찾기"를 누르면 "근거 조항"이 붙은 답 초안이 채워집니다. 금액·기준을 조항과 맞춰 본 뒤 직접 게시합니다.

규정 문서는 **가상 문서만** 올려 주세요(docx·pdf, 10MB 이하, 글자가 있는 파일). 심사위원이 직접 다른 문서를 올릴 때도 실제 규정이나 개인정보는 넣지 마세요.

단계별 기대 결과는 `docs/demo-script.md`에 있습니다.

## 사용 한도와 주의

- 채팅은 계정당 하루 **50회**, 시험 생성은 하루 **10회**, 규정 문서 처리는 **20회**, 지식 초안 생성은 **30회**까지입니다. 넘으면 "오늘 사용 한도를 넘었어요"가 표시되고, 다음 날 다시 쓸 수 있습니다. 다른 화면은 계속 정상으로 동작합니다. "문제은행에서 채우기"는 AI를 부르지 않아 한도를 쓰지 않습니다.
- 채팅 내용은 저장하지 않습니다. 새로고침하면 대화가 사라집니다.
- 에이전트는 조회·답변·초안(시험·지식) 작성만 맡고, 게시와 과제 상태는 사람이 바꿉니다. 상태는 각 화면의 버튼으로만 바뀝니다.
- 실제 개인정보나 실제 사내 문서는 넣지 말아 주세요. 파일은 담당자가 "온보딩 과제"에서 과제 서식(docx·xlsx·pdf, 10MB 이하)을 올리는 경우에만 받으며, 신입은 서류 파일을 올리지 않습니다. 서식은 가상 내용만 올려 주세요. 담당자가 "규정 문서"에서 규정 문서(docx·pdf, 10MB 이하)를 올리는 경우도 받으며, 가상 문서만 올려 주세요.
- 관리자의 "데모 데이터 초기화"는 기본 계정의 진행 상황·지식·미답변·시험·문제은행·온보딩 과제를 처음 상태로 되돌립니다(문제은행은 기본 문항만 남고, 새로 만든 과제는 보관되며, 담당자가 올린 서식은 지워지고 기본 서식 3개는 남습니다). 담당자가 올린 규정 문서는 초기화하지 않으니 필요하면 "규정 문서"에서 직접 지워 주세요. 관리자가 만든 계정은 그대로 남습니다.
