# 문제은행 + AI 출제 병행 설계

작성일: 2026-11-18 · 상태: Leo가 대화에서 흐름 승인("은행 우선, 부족분은 생성"), 문서 검토 대기
근거: `docs/superpowers/specs/2026-11-17-onboarding-agent-design.md` 목표 4(시험 출제 도우미)를 고친다.

## 1. 의도

지금 시험 출제는 "초안 만들기"마다 LLM이 문항을 새로 만든다. 서비스는 상태를 갖지 않으므로 시험끼리 문항이 겹칠 수 있고(같은 주제·난이도면 대표 문제로 수렴), 담당자가 검토해 고친 문항이 다음 시험에 쓰이지 않는다.

확정한 문항을 **팀의 문제은행**에 쌓고, 시험을 만들 때 **은행에서 먼저 채운 뒤 부족분만 AI로 만든다**. 만든 문항은 확정 때 다시 은행에 들어가므로, 시간이 지날수록 은행이 커지고 생성 호출은 줄어든다. 은행이 팀 단위라서 전사 확장 때 팀마다 다른 역량 문항을 담는 그릇이 된다.

## 2. 목표 / 비목표 / 실패 조건

**목표**
1. 시험을 확정하면 그 시험의 새 문항이 팀 은행에 들어간다. 같은 문제는 두 번 들어가지 않는다.
2. 시험 편집기의 "문제은행에서 채우기": 주제·난이도가 같은 게시 문항을 무작위로 부족분만큼 가져온다. LLM 한도를 쓰지 않는다.
3. "AI로 만들기"는 은행 문항과 지금 편집기 문항을 피할 목록으로 넘긴다. 편집기에 문항이 있으면 부족분만 만들어 뒤에 붙인다.
4. 응시 기록: 교육 담당자가 평가 과제에 어떤 확정 시험으로 봤는지 연결한다. 그 신입을 골라 은행에서 채우면 이미 본 문항은 빠진다.
5. S13 문제은행 화면: 둘러보기, 고치기, 숨기기·다시 게시, 직접 추가.
6. 이미 확정된 시험의 문항을 은행으로 옮긴다. 데모 초기화는 은행도 시드 상태로 되돌린다.

**비목표**
태그별 개수 규칙으로 시험 자동 구성, 점수·문항별 채점 기록, 시험지 PDF 업로드, 은행 문항 버전 관리, 팀 간 은행 공유, AI-04 조사 코드 일반화, 벡터 유사도로 중복 판정.

**실패 조건 (동작해도 실패)**
- 신입이 은행 문항이나 응시 기록을 볼 수 있다.
- 다른 팀 교육 담당자가 우리 팀 은행을 읽거나 쓴다.
- 같은 시험을 다시 확정 처리하거나 등록을 재시도하면 은행에 같은 문항이 또 들어간다.
- 은행에서 채우기가 하루 시험 생성 한도를 쓴다.
- 이관 중 기존 시험·문항 내용이 바뀌거나 사라진다.

## 3. 접근 방식

| 방식 | 내용 | 장단점 |
|---|---|---|
| A. 기존 문항 다시 쓰기 | 확정 시험 문항을 다른 시험으로 가져오기만 | 작다. 겹침은 담당자가 눈으로 피함, 팀 확장에 약함 |
| **B. 은행 우선 + 부족분 생성 (선택)** | 은행 테이블, 확정 시 등록, 은행 채우기, 생성 시 회피 목록, 응시 기록 | 겹침을 시스템이 줄이고 생성 도우미도 유지. 화면 하나와 테이블 둘이 늘어남 |
| C. PDF 업로드만 | 담당자가 만든 시험지를 첨부 | 가장 작다. 출제 도우미 시연이 빠지고, S12 서식은 신입이 받을 수 있어 실패 조건에 걸림 |

Leo가 B를 골랐다(규칙 기반 자동 구성은 뺀 형태).

## 4. 결정된 구조

**데이터** (마이그레이션 세 파일: 스키마·RPC·시드, 모두 추가만)
- `question_bank_items`: 팀 소속 문항. `topic`, `difficulty`(`exam_difficulty`), `prompt`, `model_answer`, `rubric`, `points`, `status`(`active`/`hidden`), `source`(`exam`/`manual`/`migrated`/`seed`), `created_by`, `created_at`, `updated_at`, 중복 판정용 `prompt_key`.
- `exam_questions.bank_item_id`: 은행에서 왔거나 은행에 등록된 문항의 출처. 은행 문항이 지워지면 `null`.
- `exam_sittings`: 시험 ↔ 평가 과제 인스턴스 연결과 연결 시점의 은행 문항 id 스냅샷(`bank_item_ids`). 쓰기는 RPC로만.
- RPC: `register_exam_to_bank`, `pick_bank_items`, `bank_prompts`, `assign_exam`. 시드 `seed_demo_bank`, `reset_demo` 갱신.
- 권한: 은행·응시 기록은 그 팀 `team_trainer`만. 신입·경영지원·관리자는 0행.

**에이전트**: `/exams/generate`에 `avoid_prompts`(최대 30개, 개당 500자)를 추가한다. 지시문에서 "AI팀" 고정을 뺀다.

**화면**
- S7 편집기: "문제은행에서 채우기" 버튼, 생성 버튼은 문항이 있으면 "부족분 AI로 만들기", 문항 카드에 "문제은행" 배지, 확정 시 은행 등록 결과 안내.
- S6 신입 상세: 평가 과제마다 "응시 시험" 연결.
- S13 문제은행 `/team/bank`(신규): 교육 담당자 메뉴 "팀 신입 현황 · 시험 출제 · 문제은행 · 지식 관리".

**단계**: 1단계(목표 1·2·3·6)는 따로 배포해도 동작한다. 2단계(목표 4·5)는 그 위에 얹는다.

## 5. 만드는 사람에게 맡기는 것

S13 레이아웃 세부(디자인 토큰·shadcn 안에서), 시드 문항 문구(가상·공개 기술 지식만), 컴포넌트 내부 구조.

## 6. 내가 정한 것 (Leo 확인 필요)

- 별도 "역량 태그" 개념 없이 시험의 `topic` 문자열을 은행 분류 키로 쓴다. 비교는 앞뒤 공백을 지우고 대소문자를 무시한 정확 일치다(저장 컬럼 `topic_key`, 은행 채우기·S13 목록 모두 같은 기준). 편집기 주제 칸에 팀 은행의 기존 주제를 자동완성으로 띄워 표기가 갈라지는 것을 줄인다.
- 확정 때 등록한 문항은 바로 게시(`active`)한다. 담당자가 이미 검토한 문항이기 때문이다.
- 편집기에서 은행 문항을 고쳐도 은행은 그대로다. 은행 수정은 S13에서만 한다. 다만 문제 문장을 새 문제로 고친 문항은 확정 때 새 은행 문항으로 등록하고 출처를 새 행으로 바꾼다(답안·채점 기준·배점만 고친 경우는 등록하지 않는다).
- 확정된 시험을 다시 저장할 때도 은행 등록을 부른다. 확정 뒤에 추가한 문항도 은행에 들어가고, 같은 문항은 두 번 들어가지 않는다.
- 같은 문항 판정: 같은 팀에서, 문제 문장의 연속 공백(줄바꿈·탭 포함)을 한 칸으로 줄이고 앞뒤 공백을 지운 값이 같으면 같은 문항이다.
- 숨긴 문항은 채우기와 회피 목록에서 빠지지만, 이미 만든 시험에는 남는다.
- 은행에서 채울 때 편집기에 이미 있는 문항은 출처 id로도, 편집기의 모든 문장(중복 판정 규칙)으로도 뺀다. 은행 조회가 실패해도 편집기 문장 회피는 유지한다. 직접 입력한 문항이 은행 문항과 같으면 다시 뽑히지 않는다.
- 회피 목록은 최대 30개, 문항당 앞 500자다. 지금 편집기 문항을 먼저 넣고, 남는 자리를 같은 주제·난이도의 게시 문항 중 최근 것으로 채운다(같은 문장은 한 번만).
- 데모 초기화 때 은행을 지우고 시드 문항(AI팀, "JavaScript 기초" 입문 8개)을 다시 넣는다.
- 응시 시험은 확정된 시험만, 같은 팀의 평가 과제에만, `blocked`·`na`가 아닐 때만 연결할 수 있다. 한 과제에 시험 여러 개(재시험)를 연결할 수 있다. 신입이 본 문항은 연결 시점의 스냅샷으로 판정하므로, 연결 뒤에 시험 문항을 고쳐도 이미 본 문항은 계속 빠진다.
