# 명함 신청(GA-07) 실제 양식 반영 설계

작성일: 2026-11-20 · 상태: 방향 A·6절 항목 사용자 결정, 시안 Leo 확인 대기. 근거: `2026-11-17-onboarding-agent-design.md` 7절 "명함 과제(GA-07)는 영문 이름 입력과 자동 채움 미리보기까지만"을 고친다.

## 1. 의도

지금 명함 신청 과제는 영문 이름 한 칸만 받고, 직급·팀·메일은 프로필에서 채운다. 실제 회사 명함 신청 양식(엑셀)은 신청자가 **영문 이름, 직급, 부문(콤보박스), 이메일 아이디, 연락처**를 직접 입력하고, 영문 직급과 영문 부문은 참고표에서 자동으로 찾는다. 심사위원과 실제 도입 시 담당자가 "회사가 실제로 받는 정보와 같다"고 느끼도록 과제 입력을 실제 양식에 맞추고, 같은 구조의 예시 엑셀 양식을 과제 첨부파일로 둔다.

## 2. 목표 / 비목표 / 실패 조건

**목표**
1. 신입이 GA-07에서 영문 이름·직급·부문·이메일 아이디·연락처 5칸을 입력해 제출한다. 부문은 목록에서 고른다.
2. 입력하는 동안 명함 미리보기가 입력값으로 바뀐다. 영문 직급·영문 부문은 참고표로 자동 표시한다.
3. 총무 담당자 업무함(S9)이 제출된 5칸과 같은 미리보기를 본다.
4. GA-07에 기본 서식 "명함 신청서.xlsx"가 첨부돼 내려받을 수 있다. 실제 양식과 시트·열·부문 드롭다운·자동 조회 구조가 같고 예시 행은 가상 인물이다.
5. 입력 칸 정의에 "목록에서 고르기"(`select`) 종류가 생겨, 다른 입력 양식 과제도 같은 방식으로 쓸 수 있다(이번에는 GA-07만 쓴다).

**비목표**: 담당자가 입력 칸을 편집하는 기능, 새 입력 양식 과제 만들기(`0010`의 "입력 양식 과제는 새로 만들 수 없습니다" 유지), 제출값으로 엑셀 생성·다운로드(원 설계의 비목표 "명함 엑셀 생성" 유지), 서버(`submit_task`)에서 입력 칸 검사 추가, 외부용 직급·자격증명·팩스번호 칸, 직급 목록 선택 강제.

**실패 조건**
- 실제 직원 이름·메일·휴대폰·팩스번호, 실제 조직명·직급 대응표·명함 표기 규정이 저장소(시드·첨부 엑셀·시안·테스트)에 들어간다(`SECURITY.md` 데이터 규칙).
- 이미 영문 이름만 제출된 GA-07 기록이 담당자 화면에서 깨지거나 비어 보인다.
- 담당자가 고친 GA-07 제목·안내문이 마이그레이션으로 덮어써진다.
- 다른 입력 양식·과제 종류의 동작이 바뀐다.

## 3. 접근 방식

| 방식 | 내용 | 장단점 |
|---|---|---|
| **A. `form_schema`에 `select` 종류 추가 (선택)** | 부문 목록과 영문명을 입력 칸 정의(데이터)에 두고, 마이그레이션으로 GA-07 칸을 5개로 바꾼다 | 웹·담당자 화면·에이전트가 같은 목록을 본다. 다른 입력 과제에 재사용. 공통 영역(`supabase/`) 변경 |
| B. GA-07 전용 화면 | 부문 목록을 웹 상수로 두고 명함 과제만 따로 그린다 | DB 변경이 거의 없어 빠르다. 목록이 코드에만 있어 엑셀·에이전트와 어긋나기 쉽다 |
| C. 담당자가 입력 칸 편집 | 템플릿 편집 화면에 칸 편집기 추가 | 가장 일반적이지만 이번 요청보다 훨씬 크다. 제외 |

사용자가 A를 골랐다(2026-11-20).

## 4. 정한 것

### 4.1 부문 목록 (가상)

실제 양식의 부문 목록은 쓰지 않는다(사용자 결정 2026-11-20, 실제 조직명 사용 취소). 실제 양식과 같은 형식("OO 사업부 / OO본부")으로 지은 가상 조직 10개와 "공란"을 쓴다. AI 조직은 시드 팀 `AI팀`의 `org_line`(AI팀·AI그룹·AI본부·AI부문)에 맞췄다. 영문 부문은 "영문명 + 조직 단위(4.6의 1.2 표)" 규칙으로 만든다.

| 부문 (`value`) | 영문 부문 (`english`) |
|---|---|
| 공란 | (빈 값: 미리보기에 부문 줄을 그리지 않는다) |
| AI 부문 | Artificial Intelligence Sector |
| AI 그룹 / AI본부 | Artificial Intelligence Group |
| 플랫폼 본부 | Platform Division |
| 클라우드 사업부 / 플랫폼본부 | Cloud Business Unit |
| 데이터 사업부 / 플랫폼본부 | Data Business Unit |
| 산업솔루션 본부 | Industrial Solution Division |
| 스마트팩토리 사업부 / 산업솔루션본부 | Smart Factory Business Unit |
| 전략컨설팅 본부 | Strategy Consulting Division |
| 경영지원 본부 | Corporate Support Division |
| 인사총무팀 / 경영지원본부 | HR & General Affairs Team |

### 4.2 직급 영문 대응표 (가상)

실제 양식의 직급표는 쓰지 않고, 시드 계정 직급(사원·대리·책임)을 포함한 일반적인 직급·직책 표기를 쓴다. 직급은 사용자 말대로 **직접 입력**이고, 입력값이 표와 정확히 같을 때만 영문 직급을 미리보기에 보인다. 표에 없으면 영문 직급 줄을 비운다.

사원→Associate, 대리→Assistant Manager, 과장→Manager, 차장→Deputy General Manager, 부장→General Manager, 선임→Senior Associate, 책임→Senior Manager, 수석→Principal, 팀장→Team Leader, 그룹장→Group Leader, 본부장→Head of Division, 부문장→Head of Sector, 대표이사→CEO.

### 4.3 입력 칸 정의 (`form_schema`)

기존 `{ fields: [{ key, label, type, required?, placeholder? }] }`에 선택 속성만 추가한다. 기존 키는 그대로 둔다.

- `type: "select"` + `options: [{ value, english? }]` — 목록에서 하나 고른다. 저장값은 `value` 문자열.
- `english: { "<입력값>": "<영문>" }` — `text` 칸의 영문 대응표(직급).
- `suffix: "@blueward.co.kr"` — 입력 칸 오른쪽에 붙는 고정 글자(이메일 도메인). 저장값에는 넣지 않는다.
- `hint` — 칸 아래 안내 한 줄.
- `format: "tel" | "email_local"` — 화면에서만 하는 형식 검사(연락처는 숫자·하이픈, 이메일 아이디는 영문·숫자·`.`·`_`·`-`). 서버 검사는 없다.

GA-07의 칸 (순서대로, 모두 필수):

| key | label | type | 비고 |
|---|---|---|---|
| `english_name` | 영문 이름 | text | 기존 키 유지. placeholder `Haneul Kim` |
| `job_title` | 직급 | text | placeholder `사원`, `english` = 4.2 표, hint "첨부 양식의 직급 표기를 따릅니다" |
| `division` | 부문 | select | `options` = 4.1 표 |
| `email_id` | 이메일 아이디 | text | `suffix` `@blueward.co.kr`, placeholder `haneul.kim` |
| `phone` | 연락처 | text | placeholder `010-0000-0000`, hint "공개 데모라 가상 번호를 입력해 주세요" |

### 4.4 미리보기 (`BusinessCard`)

- 한글 이름은 지금처럼 프로필(`full_name`)에서 온다. 나머지는 입력값이다.
- 그리는 정보: 로고, 한글 이름 + 직급, 영문 이름 + 영문 직급, 부문(영문 부문), 이메일(`email_id` + `suffix`), 연락처. 배치는 시안에서 정한다.
- 신입 화면(입력 중)과 담당자 업무함(제출 내용)이 같은 컴포넌트를 쓴다.
- **이전 기록:** `result`에 `english_name`만 있으면(기존 제출) 지금처럼 직급·팀·메일을 프로필에서 채운다. 담당자 화면의 표는 schema 칸 기준으로 그리고 없는 값은 "—"로 보인다(지금 동작).

### 4.5 데이터 반영 (새 마이그레이션)

- `public.task_templates`와 `private.task_template_seed`의 GA-07 `form_schema`를 4.3으로 바꾼다. 담당자는 `form_schema`를 고칠 수 없으므로 그대로 덮어쓴다.
- 안내문(`description`)은 새 문구("명함에 들어갈 정보를 입력해 주세요. 한글 이름은 프로필에서 채워집니다. 실제 신청 양식은 첨부한 엑셀을 참고하세요." 수준)로 바꾸되, **현재 값이 옛 시드 문구와 같을 때만** 바꾼다. seed 표는 항상 바꾼다.
- 컬럼·테이블 추가나 변경은 없다. 데이터 갱신만 한다.
- `0004_demo_data.sql`의 지식 항목("명함을 다시 만들고 싶어")은 그대로 둔다.

### 4.6 첨부 엑셀 (`supabase/seed-forms/GA-07/명함 신청서.xlsx`)

- 실제 양식과 같은 구조로 시트 2개: `명함참고`(1.1 직급표 = 4.2, 1.2 조직 단위표, 2.1 부문표 = 4.1, 2.2 표시 참고사항), `명함신청양식`. 내용은 모두 가상이다.
- `명함신청양식` 열: 이름, 영문이름, 직급, 외부용 직급, 영문직급, 자격증명, 부문, 영문부문, 이메일아이디, 휴대폰, 팩스번호. 영문직급·영문부문은 VLOOKUP, 부문은 2.1 표 범위를 가리키는 데이터 유효성(목록). 필수입력·자동선택·선택입력 범례 유지.
- 참고표 내용(원본 파일 없이 이 문서만으로 만든다):
  - 1.2 조직 단위표(조직명 / 영문): 본부 Division, 부문 Sector, 사업부 Business Unit, 그룹 Group, 센터 Center, 팀 Team. 일반 용어다.
  - 2.1 부문표: 4.1의 11행. 영문 부문은 "영문명 셀 & " " & 1.2 단위 셀" 수식으로 만든다. "공란"은 빈 값.
  - 2.2 표시 참고사항(가상 문구): 직책이 있으면 직책명을 표기(예: OOO 팀장 / Team Leader), 없으면 직급을 표기(예: OOO 책임 / Senior Manager). 표의 명칭만 쓴다. 학위·자격은 담당자와 협의해 덧붙일 수 있다.
  - 범례(필수입력·자동선택·선택입력)의 색과 셀 위치는 빌더가 정한다. 검증 기준은 시트 이름, 양식 열 순서, 부문 드롭다운 목록, VLOOKUP 결과다.
- 예시 행은 가상 값만: 김하늘 / Haneul Kim / 사원 / AI 그룹 / AI본부 / haneul.kim / 010-0000-0000. 팩스번호 칸은 비워 두고 실제 기본 팩스번호 안내는 넣지 않는다.
- `services/agent/scripts/bootstrap_forms.py`의 `SEED_FORMS`에 추가해 배포 때 올린다(기존 AC-01·HR-08과 같은 방식).
- 원본 파일은 저장소에 넣지 않는다.

### 4.7 시안·문서

- 화면 입력 구성이 바뀌므로 시안 `S3-task-detail`(입력 5칸 + 미리보기)과 `S9-ops`(제출 내용 + 미리보기)를 먼저 고쳐 Leo 확인을 받는다(`png/` 포함).
- 문서 갱신: `2026-11-17-onboarding-agent-design.md` 7절의 GA-07 줄, `docs/screens.md`(48·133행 예시), `docs/demo-script.md` 1-3, `docs/judge-guide.md` 34행, 계획서 `2026-11-17-onboarding-agent.md` GA-07 줄.

## 5. 빌더에게 맡기는 것

- 웹에서 `select` 칸은 `NativeSelect`(system.md 폼 컨트롤 규칙)를 쓴다. 고르기 전 빈 선택지 문구.
- `suffix` 표시 방식, 연락처 입력 형식 검사(하이픈 허용 수준), 이메일 아이디 글자 검사 여부.
- 미리보기 세부 배치(시안 확정 후), `BusinessCard` props 모양.
- 엑셀 생성 방법(일회성 openpyxl 스크립트 등. 스크립트를 저장소에 둘지는 빌더 판단, 결과 파일은 커밋).
- 테스트 구성: FormBody(select·suffix·필수), SubmittedResult(새·옛 기록), BusinessCard, pgTAP(마이그레이션 후 GA-07 schema·seed 일치, 안내문 조건부 갱신), bootstrap_forms 테스트.

## 6. 결정 사항

사용자가 정한 것(2026-11-20):
- 이메일 도메인 `@blueward.co.kr` 고정(명함이 회사 브랜드라서). 데모 계정 메일(`*.demo.test`)과 다르다.
- 연락처는 필수, 예시 `010-0000-0000`과 "공개 데모라 가상 번호를 입력해 주세요" 안내. 형식 검사는 숫자·하이픈 수준(서버 검사 없음).
- 부문 목록은 가상 조직명 10개 + 공란(실제 조직명 사용 취소). 보안 문서 예외는 두지 않는다.

내가 정한 것:
- 직급은 입력값 그대로 저장하고 표와 맞을 때만 영문을 보인다(목록 강제 없음). 사용자가 "직접 입력"이라 했고 원본도 자유 입력 + VLOOKUP이다.
- 직급표·표시 참고사항도 실제 양식 내용 대신 가상(일반 표기)으로 바꿨다. 실제 조직명을 빼는 결정과 같은 이유(`SECURITY.md` 원본 업무 문서 금지)다.
- 가상 조직명 11행(공란 포함)의 이름과 영문명.
- "공란"도 선택지로 둔다(원본 양식과 같게). 고르면 부문 줄을 그리지 않는다.
- 첨부 엑셀 예시 행은 시드 신입과 같은 "김하늘 / 사원 / AI 그룹 / AI본부"다.
