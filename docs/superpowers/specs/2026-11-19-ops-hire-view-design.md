# 부서 업무함 입사자별 탭 설계 (경영지원의 한 사람 과제 추가)

작성일: 2026-11-19 · 상태: 방향 B 선택(사용자), 시안 Leo 확인 대기. 근거: `2026-11-18-onboarding-plan-design.md` 5.3·5.4절을 고친다.

## 1. 의도

경영지원 담당자가 특정 신입에게 한 사람용 과제를 주려면 지금은 부서 업무함(S9)에서 "입사자" 드롭다운으로 한 명을 골라야 "이 신입에게 과제 추가" 버튼이 나타난다. 고르기 전에는 이 기능이 있다는 단서가 없다. 교육 담당자에게는 신입 중심 화면(S5→S6)이 있지만 경영지원에게는 과제 중심 표만 있다.

경영지원 담당자는 대개 특정 신입을 염두에 두고 들어온다(사용자 판단). SuccessFactors Onboarding의 "신입 목록 → 그 신입의 동작" 흐름처럼, **신입을 보고 판단한 뒤 그 줄에서 바로 과제를 추가**하게 한다.

## 2. 목표 / 비목표 / 실패 조건

**목표**
1. S9에 "입사자별" 탭: 우리 부서 과제가 있는 신입을 한 줄씩, 입사일·우리 부서 과제 진행·확인 대기 수와 함께 보인다.
2. 각 줄의 "과제 추가"로 지금과 같은 대화 상자를 연다.
3. 줄을 누르면 "전체" 탭이 그 입사자로 걸러진다.

**비목표**: 경영지원용 입사자 상세 화면·새 경로·새 메뉴, 여러 신입에게 한 번에 추가, 과제 먼저 고르는 흐름, RPC·RLS·마이그레이션 변경, 기존 입사자 드롭다운·버튼 제거.

**실패 조건**: 과제 추가 대화 상자를 쓰다가 탭이 바뀐다. 다른 부서·팀 과제가 진행·확인 대기 수에 섞인다. 기존 탭 3개의 동작이 바뀐다.

## 3. 접근 방식

| 방식 | 내용 | 장단점 |
|---|---|---|
| A. 버튼 항상 보이기 | 버튼을 늘 보이고 대화 상자 첫 칸에서 신입 선택 | 가장 작다. 신입을 고를 때 입사일·진행이 안 보여 과제 먼저 흐름에 가깝다 |
| **B. 입사자별 탭 (선택)** | S9에 탭 하나, 줄마다 "과제 추가" | 신입을 보고 판단. 데이터는 이미 화면에 있다. S9 시안 수정 필요 |
| C. 경영지원 입사자 목록·상세 신설 | `/ops/hires`, `/ops/hires/:id` | 가장 완결. 화면 둘·메뉴·시안 둘, 업무함 "전체" 탭과 겹친다. 심사 기간에 크다 |

## 4. 정한 것

- 탭 순서 `확인 대기 · 내가 처리할 일 · 입사자별 · 전체`. 기본 탭은 그대로 "확인 대기".
- 열: 입사자(이름·팀) · 입사일 · 우리 부서 과제(진행 막대 + `완료 / 전체`, 완료는 done·na) · 확인 대기 · 동작 "과제 추가".
- 대상은 지금 드롭다운 후보와 같다(우리 부서 과제가 있는 신입). 입사일 최신순.
- 줄을 누르거나 Enter → "전체" 탭 + 그 입사자 필터.
- "과제 추가" 버튼의 보이는 글자는 "과제 추가", 접근 이름은 `'이름'님에게 과제 추가`. 대화 상자는 지금과 같다(평가 없음). 추가하면 버튼 옆에 "추가했어요".
- 입사자별 탭에서는 입사자 드롭다운을 숨긴다(표가 곧 입사자 목록).
- 비어 있음: "업무함에 입사자가 없어요".

## 5. 만드는 사람에게 맡기는 것

입사자 표 컴포넌트 구성, 테스트 픽스처. 대화 상자 안의 클릭이 React 이벤트로 줄까지 올라오지 않게 동작 칸에서 막는다.
