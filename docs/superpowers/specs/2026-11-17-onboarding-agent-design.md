# 온보딩 에이전트 설계 (경진대회 시연판, 배포 포함)

작성일: 2026-11-17 · 개정 3 (배포·관리자·OpenAI 반영, 회사 CI 사용) · 상태: Leo가 대화에서 방향 확정, 문서 검토 대기

## 1. 의도

신입이 입사하면 인사·총무·회계 세 부서의 안내와 팀 교육이 흩어져 전달되고, 팀 교육 담당자는 같은 설명을 매번 반복한다. 이 제품은 회사 계정 발급 이후의 온보딩을 한 사람의 타임라인으로 묶고, 문서화되지 않은 지식에 답하는 에이전트와 시험 출제 도우미로 신입·교육 담당자·경영지원 담당자의 수고를 줄인다.

**배포가 필요한 이유**: 실제로 접속해 쓸 수 있는 웹 서비스여야 출품 의미가 있다. 기획·개발자(Leo)가 관리자로 쓰고, 심사위원이 각자 접속해 역할별로 직접 써 보며, 담당자 역할도 체험할 수 있어야 한다.

## 2. 목표 / 비목표 / 실패 조건

**목표 (시연과 심사에 반드시 등장)**
1. 신입 통합 타임라인: 경영지원 과제 21개 + AI팀 과제 10개를 입사일 / 첫 주 / 첫 달로 표시. 선행 과제가 끝나면 다음 과제가 열린다.
2. 담당자 처리 화면: 경영지원 담당자(부서별)와 교육 담당자가 확인·보완 요청·평가 기록을 하면 신입 화면에 즉시 반영된다.
3. 신입용 에이전트 채팅: 등록된 지식과 내 과제로 답한다. 모르는 질문은 신입이 "담당자에게 등록 요청"을 누르면 담당자에게 전달되고(2026-11-18 변경, `2026-11-18-knowledge-request-design.md`), 담당자가 답을 등록하면 다음 질문부터 답한다. **(갱신, 2026-11-18)** 담당자가 올린 가상 규정 문서의 조항도 검색해 "문서명 제N조" 출처로 답하고, 에이전트가 조항을 근거로 지식 초안을 만들면 담당자가 검토·게시한다(설계: `2026-11-18-policy-docs-rag-design.md`).
4. 시험 출제 도우미: 교육 담당자가 주제·난이도를 넣으면 문제·모범 답안·채점 기준 초안을 받고, 고쳐서 시험지와 답안지를 PDF로 인쇄한다. **(갱신, 2026-11-18) 문제은행 우선, 부족분 생성**: 확정한 문항은 팀 문제은행에 쌓이고, 다음 시험은 은행에서 먼저 채운 뒤 모자란 만큼만 AI로 만든다. 평가 과제에 연결한 시험의 문항은 그 신입의 다음 시험에서 빠진다(설계: `2026-11-18-question-bank-design.md`).
5. **(신규) 관리자 사용자 관리**: 관리자가 가상 계정(신입·교육 담당자·경영지원 담당자)을 등록하고, 신입이면 입사일을 넣어 온보딩을 바로 시작시킨다.
6. **(신규) 공개 배포와 한 달 운영**: 공개 URL로 접속 가능한 상태를 한 달 동안 유지한다. 심사위원이 쓰는 운영 환경에는 확인된 버전만 올라간다.
7. **(신규) 실제 도입으로 이어지는 구조**: 채택되면 MS 계정 로그인, Teams, 여러 조직으로 넓힐 수 있어야 한다.
8. **(추가, 2026-11-18) 과제 서식**: 담당자(경영지원·교육 담당자)가 자기 담당 과제에 Word·Excel·PDF 서식을 올리면, 그 과제를 받은 신입이 과제 상세에서 내려받는다.

**비목표 (발표 슬라이드의 로드맵)**
입사 전 단계(매직 링크), 오프보딩, Teams 탭·봇, Microsoft 계정 로그인, 기한 임박 자동 알림, 초대 메일 발송, 복지포인트 계산, 경비 증빙 점검, 명함 엑셀 생성, 실제 직원 계정·실제 업무 문서, 커스텀 도메인, 신입이 작성한 서식 파일을 올려 제출하기(제출은 "제출 여부"만), 서식 교체·버전 관리.

**실패 조건 (동작해도 실패)**
- 에이전트가 등록되지 않은 내용을 지어내 답한다.
- 신입이 시험 문제·답안이나 다른 사람의 과제·평가 메모를 볼 수 있다.
- 실명, 주민번호·계좌·카드번호 같은 민감정보나 실제 내부 업무 문서가 데이터나 화면, 시드 서식 파일에 들어간다. (회사 CI — 회사명·로고·테마 색상 — 는 브랜딩 용도로 허용, §5 브랜딩)
- **(추가)** 신입이나 담당 범위 밖 사용자가 과제 서식을 올리거나 지울 수 있다. 다른 조직 사용자가 서식을 내려받을 수 있다.
- 에이전트가 과제 상태를 바꾼다.
- **(신규)** OpenAI 키나 Supabase 관리자 키가 브라우저 코드·저장소에 노출된다.
- **(신규)** 관리자가 아닌 사용자가 계정을 만들거나 데모 데이터를 초기화할 수 있다.
- **(신규)** URL을 아는 누구든 제한 없이 LLM을 호출해 비용을 키울 수 있다.
- **(신규)** 운영 기간 중 서비스가 내려가 있거나 첫 요청이 수십 초 걸린다.
- **(신규)** 개발 중인 변경이 확인 없이 운영에 반영되어 심사위원 화면이 깨진다.
- **(신규)** 로그인 화면이나 저장소에 계정 비밀번호가 노출된다.

## 3. 제약

- 기한: 이번 주(금) 안에 배포·시연 준비 완료. 코딩 에이전트 여러 개가 병렬로 작업 후 합친다. 커밋·PR·머지는 Claude Code CLI가 맡는다.
- 데이터: 시나리오는 "우리 회사 사람들이 쓰는 상황"이다. 화면 브랜딩과 시드 조직명은 회사 CI(Blueward)를 쓰고, 사람·계정·과제·지식은 전부 가상이다.
- LLM: OpenAI 유료 API (키는 Leo 제공). 유료 API 입력은 학습에 쓰이지 않는다.
- 클라우드: Leo에게 익숙한 GCP 중심. DB·인증은 Supabase 클라우드.
- 운영 기간: 한 달 동안 계속 켜 둔다. Supabase 무료 플랜은 7일 동안 활동이 없으면 멈추고 백업이 없어 운영에는 쓰지 않는다.
- 접속: 심사위원에게는 역할별 계정 정보를 따로 전달한다.
- 플러그인: 조직 정책상 공식 Anthropic 마켓플레이스 플러그인만 설치 가능.
- 근거 문서: 「IT서비스·WX 온·오프보딩 통합 업무 명세」(2026-11-16). 업무 ID, 선행 관계, 상태 구분, "자동 실행하지 않는다" 원칙을 따른다. 실명·금액·세부 규정은 가상 값으로 바꾸고, 원본 문서는 저장소에 넣지 않는다.

## 4. 접근 방식

### 4.1 제품 구조

| 방식 | 내용 | 장단점 |
|---|---|---|
| A. 에이전트 중심 | 과제 조회·완료까지 모두 채팅으로 | 인상적이지만 LLM 실수가 업무 상태를 망가뜨리고 시연이 불안정 |
| **B. 업무 엔진 + 얇은 에이전트 (선택)** | 과제 상태는 DB 함수와 화면이 관리, 에이전트는 조회·답변·출제만 | 안정적, 프레임워크 교체가 쉬움. 채팅의 "실행" 능력은 제한 |
| C. Q&A 챗봇만 | 지식 답변만 | 가장 빠르지만 "통합 온보딩" 의도를 못 보여 줌 |

### 4.2 배포 구조

| 방식 | 내용 | 장단점 |
|---|---|---|
| **A. 웹·DB·에이전트 분리 배포 (선택)** | 웹 정적 호스팅 + Supabase 클라우드 + 에이전트 컨테이너 | 기존 계획 유지, ADK 유지, PR별 미리보기 가능. 플랫폼 여러 개 |
| B. TypeScript 단일 스택 | 에이전트·관리자 API를 서버리스 함수(OpenAI SDK)로 | 배포 가장 단순. ADK를 버려 팀 자산·확장 계획과 멀어지고 에이전트 작업 재작성 |
| C. 컨테이너 하나 | FastAPI가 웹 파일·에이전트·관리자 API를 모두 서빙 | 배포 단위 하나. 미리보기 없음, 웹만 고쳐도 전체 재배포 |

Leo가 A를 골랐고, 에이전트를 ADK로 만들며 GCP가 익숙하다는 이유로 에이전트는 **Cloud Run**, 웹은 **Firebase Hosting**으로 정했다. LiteLLM을 거친 OpenAI 연동이 막히면 에이전트 내부만 OpenAI SDK 직접 호출로 바꾼다.

### 4.3 운영 방식

| 방식 | 내용 | 장단점 |
|---|---|---|
| **A. 스테이징·운영 분리 + 운영 DB 유료 (선택)** | `main` 머지 → 스테이징 자동 배포, 태그 → 운영 배포. 운영은 Supabase Pro | 한 달 운영과 계속 개발을 함께 할 수 있다. 환경 두 개 설정과 월 비용 |
| B. 전부 GCP | Cloud SQL + Firebase Auth + Cloud Run | 클라우드 하나. RLS·실시간·인증을 다시 만들어야 해 이번 주에는 불가능. 실제 도입이 정해지면 검토 |
| C. 단일 환경 무료 | 머지가 곧 운영 반영, Supabase 무료 | 가장 싸다. 자동 멈춤·백업 없음·머지 사고가 그대로 심사위원에게 간다 |

Leo가 A를 골랐다.

## 5. 결정된 구조

**구성**
- **웹**: React + Vite + TypeScript, Tailwind + shadcn/ui, supabase-js + TanStack Query. Firebase Hosting(SPA 리라이트). PR마다 미리보기 채널.
- **환경**: 로컬(개발), 스테이징(`main` 최신, PR 미리보기의 백엔드), 운영(심사위원 접속).
- **데이터·인증**: Supabase 클라우드 프로젝트 2개(운영은 Pro·서울 리전, 스테이징은 별도 무료 조직). 개발은 로컬 Supabase. 공개 가입은 끈다. 상태 전이는 Postgres 함수(RPC)로만 한다.
- **에이전트 서비스**: Python + FastAPI + Google ADK, 모델은 LiteLLM 연결로 OpenAI(모델명은 환경변수 `OPENAI_MODEL`). Cloud Run, 서울 리전(`asia-northeast3`). SSE 스트리밍. 요청 사이에 상태를 갖지 않는다(대화 이력은 요청에 담겨 온다).
- **관리자 API**: 에이전트 서비스 안의 `/admin/*`. 호출자 토큰이 `admin` 역할인지 확인한 뒤에만 Supabase 관리자 키로 계정을 만든다. 관리자 키는 이 경로에서만 쓴다.
- **비밀값**: `OPENAI_API_KEY`, `SUPABASE_SERVICE_ROLE_KEY`는 GCP Secret Manager에만 둔다. 웹에는 Supabase 공개 키와 에이전트 URL만 들어간다.
- **배포 자동화**: GitHub Actions. PR → 테스트 + 웹 미리보기 배포. `main` 머지 → 스테이징에 마이그레이션·에이전트·웹 배포 후 점검 스크립트. `v*` 태그(Leo만 만든다) → 운영에 같은 순서로 배포.
- **로그인**: 이메일·비밀번호만. 로그인 화면에 데모 계정 버튼을 두지 않는다. 기본 계정 6개(관리자, 신입, 교육 담당자, 인사, 총무, 회계)는 배포 때 스크립트가 만들고 비밀번호는 비밀 저장소에서 받는다.
- **브랜딩(개정 3)**: 회사 CI를 쓴다. 회사명 `Blueward`, 로고(전체·심볼·워드마크), 테마 색상·라운드·글꼴 토큰은 `docs/design/onboarding-design/`을 따른다. 시드 조직명은 회사명, 사람 이름과 계정 메일(`@demo.test`)은 가상이다.
- **실제 도입 경로**: MS 계정 로그인은 Supabase Auth의 Azure 연동, Teams 봇은 같은 에이전트 API 호출, 여러 조직은 `org_id`, 전부 GCP로 옮길 때는 Postgres 스키마를 그대로 가져간다.

**도메인 규칙**
- **역할**: `new_hire`, `team_trainer`, `ops_staff`(부서 `hr` / `ga` / `accounting`), **`admin`(신규)**.
- **과제 상태**: `blocked` → `todo` → `submitted` → `rework` → `done`, 별도로 `na`(사유 필수).
- **완료 방식**: `self`, `confirm`, `staff_only`.
- **과제 유형**: `ops`, `read`, `input`, `practice`, `setup`, `assessment`.
- **지식 검색**: 지식은 벡터 DB 없이 권한 범위 안의 게시된 지식 전체를 넘기고 모델이 고른다. **(변경, Leo 승인 2026-11-18)** 채팅은 도구 호출 없이 모델을 한 번만 부른다. 서버가 지식·과제를 사용자 토큰으로 미리 조회해 지시문에 짧은 키로 넣고, 모델은 답 끝 표시로 근거를 알린다(응답 시간: 지식 질문의 첫 글자 8~10초 → 약 3초). **(변경, Leo 승인 2026-11-18)** 담당자가 올린 가상 규정 문서는 조항 단위로 pgvector 임베딩 검색한다(설계: `2026-11-18-policy-docs-rag-design.md`).
- **에이전트 권한**: 사용자의 Supabase 토큰으로 조회해 RLS가 그대로 적용된다. 과제 상태를 바꾸는 도구는 없다. **(변경, 2026-11-18)** 지식 초안을 만들 수 있지만 저장·게시는 담당자가 한다. 문서 색인만 담당자 토큰으로 저장한다.
- **확장 대비**: 모든 테이블에 `org_id`, 토큰 검증은 한 모듈, 업무 로직은 ADK 밖, 특정 모델 전용 기능 미사용.

**신규 화면**
- **S11 사용자 관리** `/admin/users` (관리자): 사용자 목록, 계정 등록(이름·메일·역할·부서·소속 팀·초기 비밀번호, 신입이면 입사일 → 온보딩 자동 시작), 데모 데이터 초기화.

화면 전체는 `docs/screens.md`, 테이블·API 세부는 구현 계획에 있다.
