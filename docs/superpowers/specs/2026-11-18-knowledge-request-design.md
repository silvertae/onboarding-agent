# 미답변 질문을 신입의 "등록 요청"으로 바꾸기 (짧은 설계)

작성일: 2026-11-18 · 상태: Leo 승인

## 의도

지금은 채팅이 근거를 못 찾으면 에이전트의 `log_unanswered` 도구가 `unanswered_questions`에 자동으로 기록한다. 그러면 S10 미답변 탭에 신입이 원하지 않은 질문까지 쌓이고, 에이전트가 DB에 쓰는 유일한 경로가 남는다. 담당자에게는 신입이 실제로 원한 요청만 가게 하고, 에이전트는 조회·답변만 하게 한다.

## 목표

- 근거 없는 답변(`unanswered` 이벤트) 아래에만 "담당자에게 등록 요청" 버튼을 보인다.
- 버튼을 누르면 직전 질문이 채워진 확인 창이 열린다. 신입이 고칠 수 있다(1000자까지).
- 보내면 웹이 신입 본인 권한으로 `unanswered_questions`에 기록한다. S10 미답변 탭은 지금 그대로다.

## 비목표

받는 담당자 선택(지금처럼 팀 교육 담당자 + 경영지원), 근거 있는 답변에서의 요청, 요청 상태 추적 화면, 스키마 변경.

## 실패 조건

- 에이전트가 여전히 DB에 쓴다.
- 신입이 누르지 않았는데 요청이 생긴다.
- 같은 답변에서 버튼을 여러 번 눌러 중복 요청이 생긴다.

## 접근 방식

| 방식 | 판단 |
|---|---|
| **A. 웹이 신입 권한으로 직접 insert** | **선택.** 기존 RLS "본인 질문 기록"(`0002_rls.sql`)이 본인·조직·팀을 검사한다. 마이그레이션이 없다. |
| B. 에이전트에 요청 엔드포인트·도구 | 에이전트가 DB에 쓰게 되어 이번 변경의 목적과 반대. |
| C. 새 RPC | RLS 이상의 검증 이득이 없다. "과제 상태는 RPC로만" 규칙은 이 테이블에 해당하지 않는다. |

## 정한 것

- 에이전트: `log_unanswered`를 DB 쓰기 없는 `mark_unanswered()`로 바꾼다. `unanswered` 이벤트 신호만 내고, 요청당 한 번만 보낸다. 고정 답은 "확인되지 않은 내용이에요."(전달했다는 말을 뺀다).
- 중복 방지: 답변마다 요청 id(`crypto.randomUUID()`)를 하나 만들어 insert에 넣고 다시 보낼 때도 같은 id를 쓴다. 저장은 됐는데 응답을 못 받은 경우 재시도는 기본키 중복(`23505`)이 나므로 보낸 것으로 본다(Codex 리뷰 반영).
- `unanswered` 이벤트의 뜻은 "근거 없음(기록하지 않음)"으로 바뀐다. 이벤트 형식은 그대로다.
- 화면 문구: 버튼 "담당자에게 등록 요청" / 창 제목 "담당자에게 답 등록을 요청할까요?" / 안내 "담당자가 답을 등록하면 같은 질문에 답할 수 있어요." / 완료 문구 "담당자에게 요청했어요. 답이 등록되면 같은 질문에 답할 수 있어요."(버튼 자리, `role="status"`, 포커스 이동 — 디자인 리뷰에서 비활성 버튼 대신으로 바꿈) / 실패 "요청을 보내지 못했어요. 다시 시도해 주세요."

## 구현하는 사람에게 맡기는 것

확인 창의 세부 배치(디자인 시스템 규칙 안에서), 직전 질문을 찾는 방법.
