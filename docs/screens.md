# 화면 명세 (시안 작업용)

화면은 14개다. 로그인 1, 신입 3, 교육 담당자 5, 경영지원 1, 공용 3(S10 지식, S12 온보딩 과제, S14 규정 문서), 관리자 1.
공개 주소로 배포되어 심사위원이 직접 접속한다. 계정 정보는 화면에 노출하지 않고 따로 전달한다.
데스크톱 1440px 기준, 신입 화면(S2~S4)만 모바일 폭도 고려한다. 모든 문구는 한국어, 브랜딩은 회사 CI(Blueward), 사람·계정·업무 데이터는 가상이다.

## 공통 요소

- **상단 바**: 서비스 이름, "데모 환경 · 가상 데이터" 표시, 역할별 메뉴, 로그인한 사람 이름·역할 배지(신입 / 교육 담당자 / 경영지원 / 관리자), 로그아웃.
- **상태 배지** (전 화면 동일):

| 값 | 표시 문구 | 의미 |
|---|---|---|
| `blocked` | 선행 과제 대기 | 잠김. 어떤 과제가 끝나야 열리는지 함께 표시 |
| `todo` | 할 일 | 신입이 할 차례 (staff_only 과제는 "담당자 처리 예정") |
| `submitted` | 확인 대기 | 신입이 제출, 담당자 확인 전 |
| `rework` | 보완 요청 | 담당자가 사유와 함께 되돌림 |
| `done` | 완료 | |
| `na` | 해당 없음 | 사유 표시 |

- **담당 표시**: 과제마다 인사팀 / 총무팀 / 회계팀 / AI팀 배지.
- **단계**: 입사일 / 첫 주 / 첫 달.

## S1. 로그인 `/login`

- 누가: 전체
- 기능: 이메일·비밀번호 로그인만 있다. 회원가입, 비밀번호 찾기, 데모 계정 바로 들어가기 버튼은 없다(계정은 관리자가 만들어 따로 전달). 로그인 후 역할에 따라 `/me`, `/team`, `/ops`, `/admin/users`로 이동.
- 보이는 것: 서비스 한 줄 소개, "가상 데이터로 운영되는 데모입니다. 계정은 안내받은 정보를 사용해 주세요" 안내.
- 상태: 로그인 실패 안내("메일 또는 비밀번호를 확인해 주세요").

## S2. 신입 홈 (타임라인) `/me`

- 누가: 신입
- 보이는 것: 이름, 입사 며칠째, 전체 진행률(완료+해당 없음 / 전체), "지금 할 일" 묶음(`todo`·`rework` 과제), 단계별(입사일 / 첫 주 / 첫 달) 과제 목록. 과제 행에는 제목, 담당 배지, 상태 배지, 기한, 잠긴 경우 "○○ 완료 후 열림", 서식이 있으면 클립 아이콘과 "서식 N".
- 기능: 담당(전체 / 경영지원 / AI팀) 필터, 과제 행 클릭 → S3. 담당자가 상태를 바꾸면 새로고침 없이 반영.
- 상태: 모두 완료 시 축하 상태. 보완 요청 과제는 맨 위에 강조.

## S3. 과제 상세 `/me/tasks/:id`

- 누가: 신입
- 공통 영역: 제목, 담당, 상태, 기한, 설명(안내문), 선행 과제, 보완 요청 사유(있을 때), "이 과제에 대해 물어보기" 버튼(S4를 열고 과제 제목을 미리 채움).
- 유형별 본문과 행동:

| 유형 | 본문 | 버튼 |
|---|---|---|
| `ops` / `practice` | 안내문, 외부 링크 | 완료(self) 또는 제출(confirm) |
| `read` | 읽을 내용 | 읽었어요 |
| `input` | 입력 양식 (예: 기술스택·경력 조사, 명함 영문 이름 + 자동 채움 미리보기) | 제출 |
| `setup` | 하위 체크리스트 (예: SAP 계정, cf cli, mbt, cds cli) | 전부 체크 시 완료 |
| `assessment` | 일정·장소, 결과(통과 / 보충 필요)와 메모 | 없음 (교육 담당자가 기록) |

- 작성할 서식: 담당자가 올린 서식이 있을 때만 "안내" 바로 아래에 보인다. 없으면 섹션 자체를 그리지 않는다.
  - 파일 행: 형식 아이콘, 파일 이름(길면 가운데를 줄이고 확장자는 남김), "Excel · 48KB"처럼 형식과 크기, "내려받기" 버튼. 모바일은 44px 아이콘 버튼.
  - 내려받기는 누를 때 60초짜리 서명 URL을 만들어 원본 파일 이름으로 받는다. 잠긴 과제·완료한 과제에서도 받을 수 있다.
  - 상태: 내려받는 중(그 버튼만 비활성), 실패("파일을 내려받지 못했어요. 다시 시도해 주세요." 행 아래 표시).
  - 순서: 기본 서식 먼저, 그다음 올린 순서대로.
  - 목록 불러오기 실패: 섹션 자리에 "서식을 불러오지 못했어요. 다시 시도해 주세요." + "다시 불러오기"(LoadError, `size="lg"`).
  - 시안: `docs/design/onboarding-design/screens/S3-task-detail-forms.html`, `S3-task-detail-forms-mobile.html`.
- 해당 없음: 허용된 과제만 "해당 없음" 버튼 → 사유 입력 필수.
- `staff_only` 과제: 버튼 없이 "담당자가 처리하면 완료됩니다" 안내.

## S4. 에이전트 채팅 패널 (S2·S3 오른쪽에 고정, 모바일은 전체 화면)

- 누가: 신입
- 보이는 것: 대화 목록, 답변 아래 출처(규정 원문 조항, 근거 지식 제목, 관련 과제 링크), 추천 질문 칩 3개(예: "오늘 뭐 해야 해?", "회의실 예약 어떻게 해?", "노트북 경비 계정과목이 뭐야?").
- 기능: 질문 입력, 답변 스트리밍 표시, 관련 과제 클릭 → S3, 근거 없는 답변에서 "담당자에게 등록 요청".
- 담당자에게 등록 요청: 근거 없는 답변(`unanswered`) 아래에만 버튼이 있다. 누르기 전에는 아무것도 기록하지 않는다. 누르면 창("담당자에게 답 등록을 요청할까요?" / "담당자가 답을 등록하면 같은 질문에 답할 수 있어요.")에 직전 질문이 채워지고, 신입이 고쳐서 "요청 보내기" → S10 미답변에 올라간다. 보낸 뒤 버튼 자리에 완료 문구("담당자에게 요청했어요. 답이 등록되면 같은 질문에 답할 수 있어요.", `role="status"`, 포커스 이동)가 남는다. 실패하면 창 안에 "요청을 보내지 못했어요. 다시 시도해 주세요."
- 규정 원문(2026-11-18 추가): 답이 담당자가 올린 규정 문서의 조항에 근거하면 답변 아래 "규정 원문" 줄에 "문서명 제N조 제목" 칩(FileText 아이콘)을 둔다. "근거"(검토된 지식)·"관련 과제"보다 위에 둔다. 칩을 누르면 조항 창(데스크톱 Dialog, 모바일 아래 시트)에 문서명·범위, 조항 제목, 조항 본문(텍스트로만), 안내 "담당자가 검토한 답이 아니라 규정 원문에서 찾은 내용이에요. 정확한 적용은 담당 부서에 확인해 주세요.", "닫기"(44)를 둔다. 답 본문은 "복리후생 규정 제8조에 따르면"처럼 문서명과 조항을 말한다. 시안 `S4-chat-sources`.
- 답변 기다리는 중(2026-11-18 추가): 보낸 직후부터 첫 글자가 올 때까지 답변 자리에 점 세 개와 "사내 지식과 내 과제를 확인하고 있어요"를 둔다. 8초가 지나도 첫 글자가 없으면 문구를 "답변이 조금 늦어지고 있어요. 잠시만 기다려 주세요."로 바꾼다. 첫 글자가 오면 바로 답변으로 바뀐다. 시안 `S4-chat-states` ②·③.
- 새 대화(2026-11-19 추가): 대화가 있을 때만 헤더의 닫기 버튼 왼쪽에 "새 대화" 아이콘 버튼(MessageSquarePlus)을 둔다. 답변을 받는 중에는 누를 수 없다. 누르면 확인 창("새 대화를 시작할까요?" / "지금 대화는 저장되지 않아 다시 볼 수 없어요.", "취소"·"새 대화 시작")을 띄우고, 시작하면 대화를 비우고 추천 질문 화면으로 돌아간다. 다음 질문은 이전 대화 없이 보낸다. 대화는 어디에도 저장하지 않는다.
- 상태: 답변 기다리는 중, 답변 중, 모르는 질문("확인되지 않은 내용이에요." + 등록 요청 버튼), 서비스 연결 실패 안내와 다시 시도, 하루 사용 한도 초과 안내("오늘 사용 한도를 넘었어요"). 질문은 1000자까지.

## S5. 팀 신입 현황 `/team`

- 누가: 교육 담당자
- 보이는 것: 우리 팀 신입 카드(이름, 입사일, 팀 과제 진행률, 확인 대기 수, 예정된 평가 일정), 상단에 미답변 질문 수 → S10.
- 기능: 카드 클릭 → S6.

## S6. 신입 상세 `/team/hires/:id`

- 누가: 교육 담당자
- 보이는 것: 팀 과제 목록과 상태, 신입이 제출한 기술스택·경력 조사 결과, BTP 세팅 체크리스트 진행 상황, 평가 과제 2개(간단 코딩테스트, JS 기본기 테스트).
- 기능: 평가 일정·장소 입력, 결과(통과 / 보충 필요)와 메모 기록, `confirm` 과제 확인 / 보완 요청(사유 필수), "이 신입 기준으로 시험 만들기" → S7(조사 결과를 참고 자료로 전달).
- 응시 시험: 평가 카드 아래 줄. 연결한 시험 제목 목록(각각 S8 시험지로), 확정된 시험만 담은 선택 + "연결"(`assign_exam`). 이미 연결한 시험은 선택지에서 빠진다. 한 과제에 여러 시험(재시험)을 연결할 수 있다. 과제가 선행 과제 대기·해당 없음이면 줄을 그리지 않는다. 연결한 시험의 은행 문항은 그 신입의 다음 시험을 은행에서 채울 때 빠진다(연결 시점 스냅샷).
- 이 신입에게 과제 추가: 팀 과제 표 위 "이 신입에게 과제 추가". 대화 상자 제목 "'이름'님에게 과제 추가", 안내 "이 신입에게만 들어가고, 바로 할 일로 보여요." 칸은 S12 편집 칸에서 선행 과제를 뺀 것. 동작 "취소"·"추가". 추가된 과제는 목록에서 "이 신입만" 배지. 빼려면 해당 없음으로 처리한다.
- 한 사람용 과제 빼기: "이 신입만" 과제(완료·해당 없음 전)는 행의 "처리" → 과제 상세 패널 아래 "해당 없음" → "해당 없음 사유"(필수) → "해당 없음으로 처리". 해당 없음 허용과 상관없이 뺄 수 있고, 기본 과제에는 이 동작이 없다. 문구는 S3 해당 없음과 같고, 사유 칸 안내는 보완 요청과 같다("신입에게 보여질 사유를 적어 주세요"), 실패하면 다른 처리 동작처럼 패널 안 오류 문구.
- 주의: 경영지원 과제는 보이지 않는다.

| 상황 | 문구 |
|---|---|
| 추가함 | 추가했어요 |
| 추가 실패 | 추가하지 못했어요. 다시 시도해 주세요. |
| 연결한 시험 없음 | 아직 연결한 시험이 없어요. |
| 확정된 시험 없음 | 확정된 시험이 없어요. 시험 출제에서 먼저 확정해 주세요. |
| 연결함 | 연결했어요 |
| 연결 실패 | 시험을 연결하지 못했어요. 다시 시도해 주세요. |
| 응시 시험 불러오기 실패 | 응시 시험을 불러오지 못했어요. 다시 시도해 주세요. |

## S7. 시험 출제 `/team/exams`, `/team/exams/:id`

- 누가: 교육 담당자
- 목록: 만든 시험(제목, 주제, 난이도, 문항 수, 초안 / 확정).
- 편집기 왼쪽: 주제(팀 문제은행의 기존 주제를 자동완성), 난이도(입문 / 중급), 문항 수(1~10), 문항 스타일(예: 손으로 푸는 코드 읽기), 참고할 신입 선택(선택), 버튼 두 개를 위아래로: "문제은행에서 채우기"(위, 테두리 버튼), "초안 만들기"(아래, 기본 버튼. 문항이 있으면 "부족분 AI로 만들기").
  - "문제은행에서 채우기": 같은 주제(대소문자·앞뒤 공백 무시)·난이도의 게시 문항을 문항 수까지 모자란 만큼 무작위로 가져와 뒤에 붙인다. 생성 한도를 쓰지 않는다. 편집기에 있는 문항(출처와 문장)과 참고할 신입이 이미 본 문항은 빠진다.
  - "부족분 AI로 만들기": 모자란 만큼만 만들어 뒤에 붙인다. 편집기 문항과 은행 문항 문장을 피할 목록으로 넘긴다. 문항 수만큼 차면 두 버튼 모두 비활성.
- 편집기 오른쪽: 문항 카드(문제, 모범 답안, 채점 기준, 배점). 은행에서 온 문항은 "문제은행" 배지(고쳐도 유지, "다시 만들기"로 바꾸면 사라짐). 문항별 수정, "다시 만들기"(지시 한 줄 입력 가능), 삭제, 순서 변경, 문항 추가.
- 기능: 저장, 확정, "시험지 인쇄" / "답안지 인쇄" → S8. 확정하면(그리고 확정된 시험을 다시 저장하면) 새 문항을 팀 문제은행에 넣는다. 같은 문제는 두 번 들어가지 않는다. 등록이 실패해도 시험은 확정된 채로 두고 "다시 시도" 버튼을 보인다.
- 상태: 생성 중, 생성 실패 안내와 다시 시도, 하루 사용 한도 초과 안내, "AI가 만든 답안은 확정 전 검토가 필요합니다" 안내 문구.
- 문제은행 상태(은행 채우기 결과는 버튼 아래, 확정 결과는 머리 아래 알림 자리):

| 상황 | 문구 |
|---|---|
| 은행에서 가져오는 중 | 문제은행에서 가져오는 중… |
| 은행 부족 (N = 가져온 개수) | 문제은행에 맞는 문항이 N개뿐이에요. 나머지는 AI로 만들어 주세요. |
| 은행에 없음 | 문제은행에 이 주제·난이도 문항이 아직 없어요. AI로 만들어 주세요. |
| 은행 불러오기 실패 | 문제은행을 불러오지 못했어요. 다시 시도해 주세요. |
| 확정 + 등록 | 확정했어요. 새 문항 N개를 문제은행에 넣었어요. (N = 0이면 "확정했어요.") |
| 등록 실패 | 확정했지만 문제은행에 넣지 못했어요. 다시 시도해 주세요. |

- 시안: `docs/design/onboarding-design/screens/S7-exam-editor.html`.

## S9. 부서 업무함 `/ops`

- 누가: 경영지원 담당자 (자기 부서 과제만)
- 보이는 것: 상단 요약(확인 대기 / 보완 요청 중 / 진행 중 입사자 수), 탭(확인 대기 · 내가 처리할 일 · 입사자별 · 전체), 표(입사자, 과제, 상태, 제출 시각, 기한). 입사자별 탭은 표가 다르다(아래).
- 행 클릭 시 오른쪽 상세 패널: 과제 안내, 신입이 제출한 내용(예: 명함 영문 이름과 자동 채움 미리보기), 해당 없음 사유.
- 기능: 확인(완료 처리), 보완 요청(사유 필수), `staff_only` 과제 완료 처리(예: 지문 등록, 복지포인트 등록), 입사자별 필터.
- 입사자 필터: 표 머리 오른쪽, 탭 묶음과 같은 회색 상자 안에 라벨 "입사자"(system.md "표 머리의 거르기 select"). 입사자별 탭에서는 보이지 않는다.
- 입사자별 탭(2026-11-19 추가): 우리 부서 과제가 있는 신입을 입사일 최신순으로 한 줄씩. 열은 입사자(이름·팀), 입사일, "○○팀 과제"(진행 막대 + `완료 / 전체`, 완료는 완료·해당 없음), 확인 대기 수, 동작 "과제 추가"(접근 이름 "'이름'님에게 과제 추가"). 줄을 누르면 "전체" 탭이 그 입사자로 걸러진다. 비어 있으면 "업무함에 입사자가 없어요".
- 이 신입에게 과제 추가: 입사자별 탭 각 줄의 "과제 추가", 또는 다른 탭에서 입사자 필터로 한 명을 고른 상태의 "이 신입에게 과제 추가". 대화 상자·"이 신입만" 배지·문구는 S6과 같다(종류에 평가 없음). 추가하면 버튼 옆에 "추가했어요".
- 한 사람용 과제 빼기: "이 신입만" 과제(완료·해당 없음 전)는 오른쪽 상세 패널 아래 "해당 없음" → "해당 없음 사유"(필수) → "해당 없음으로 처리". S6과 같다.
- 주의: 신입이 서류 파일을 올리는 기능은 없다. "제출 여부"만 다룬다. 신입에게 줄 서식은 S12 온보딩 과제에서 관리한다.

## S10. 지식·미답변 관리 `/knowledge`

- 누가: 교육 담당자(우리 팀 지식), 경영지원 담당자(회사 공통 지식)
- 탭 1 미답변 질문: 신입이 채팅에서 등록을 요청한 질문, 요청한 시각, 요청한 사람의 팀. "답 등록" → 질문이 채워진 지식 작성 폼 → 게시하면 미답변이 해결됨으로 바뀐다.
- 탭 2 지식 목록: 질문, 답변, 분류, 범위(회사 공통 / AI팀), 상태(초안 / 게시), 수정일. 검색, 추가, 수정, 게시 / 게시 취소.
- 규정에서 답 초안 찾기(2026-11-18 추가): 지식 작성 폼의 "답변" 라벨 오른쪽 버튼(32). 누르면 "찾는 중…"(비활성) + 답변 칸 스켈레톤 + "규정 조항에서 근거를 찾고 있어요." 찾으면 답변(·분류) 칸을 채우고 아래에 "근거 조항" 칩, 경고 안내 "AI가 규정 조항으로 만든 초안이에요. 금액·기준이 조항과 맞는지 확인하고 게시해 주세요."를 둔다. 담당자가 고쳐서 게시한다. 근거가 없으면 "올린 규정 문서에서 근거를 찾지 못했어요. 답을 직접 써 주세요.", 실패하면 "초안을 만들지 못했어요. 잠시 후 다시 시도해 주세요." 읽을 수 있는 규정 문서가 없으면 버튼을 막고 "올린 규정 문서가 없어요. 규정 문서에서 먼저 올려 주세요."(S14 링크). 교육 담당자도 회사 공통 규정으로 찾을 수 있다.
- AI 작성 지식: 에이전트가 만든 지식은 질문 아래 "AI 작성" 배지(회색 pill, Sparkles 아이콘)를 단다. 게시한 뒤에도 남는다. 지식 목록 머리 아래 필터 칩 "전체 N" / "AI 초안 N"(AI 작성이면서 초안). 근거 조항이 있으면 "근거" 칸에 조항 번호, 편집 폼에 근거 조항 칩. 필터 "AI 초안"에 해당하는 지식이 없으면 "AI 초안이 없어요".
- 상태: 미답변 없음 상태.
- 메뉴: 교육 담당자·경영지원 메뉴 끝에 "규정 문서"(S14)를 더한다.

## S11. 사용자 관리 `/admin/users`

- 누가: 관리자
- 보이는 것: 사용자 표(이름, 메일, 역할, 부서 또는 팀, 입사일, 기본 계정 여부), 역할 필터, 전체 사용자 수.
- 계정 등록(오른쪽 패널 또는 대화 상자): 이름, 메일, 직급, 역할(신입 / 교육 담당자 / 경영지원), 초기 비밀번호(8자 이상). 역할에 따라 칸이 바뀐다.

| 역할 | 추가로 받는 값 |
|---|---|
| 신입 | 소속 팀, 입사일, 본사 출입 대상 여부 → 등록하면 온보딩 과제가 바로 만들어진다 |
| 교육 담당자 | 소속 팀 |
| 경영지원 | 부서(인사 / 총무 / 회계) |

- 기능: 계정 등록, "데모 데이터 초기화"(기본 계정의 진행 상황·지식·미답변·시험을 처음 상태로, 담당자가 올린 서식은 지우고 기본 서식은 유지. 확인 창에 "초기화" 입력 필요. 관리자가 만든 계정은 유지).
- 상태: 등록 성공 안내("계정을 만들었어요. 메일과 비밀번호를 전달해 주세요"), 이미 등록된 메일, 등록 실패와 다시 시도, 초기화 진행 중·완료.
- 주의: 관리자 계정은 이 화면에서 만들 수 없다. 계정 수정·삭제는 없다. 관리자는 과제·시험·지식 화면에 들어가지 않는다.

## S12. 온보딩 과제 `/tasks`

- 누가: 교육 담당자(우리 팀 과제), 경영지원 담당자(우리 부서 과제). 메뉴: 교육 담당자 "팀 신입 현황 · 시험 출제 · 문제은행 · 온보딩 과제 · 지식 관리", 경영지원 "부서 업무함 · 온보딩 과제 · 지식 관리".
- 머리말: "○○ 신입에게 들어갈 온보딩 과제를 관리해요. 새로 만든 과제는 이후 온보딩을 시작하는 신입부터 들어가요." 오른쪽에 "과제 추가"(주요 동작).
  - ○○: 교육 담당자는 "AI팀 신입에게 들어갈 …"처럼 팀 이름. 경영지원은 앞 문장을 "모든 신입에게 들어갈 인사팀 과제를 관리해요."처럼 쓴다(부서 이름: 인사팀 / 총무팀 / 회계팀).
- 왼쪽 목록: 단계(입사일 / 첫 주 / 첫 달)별 묶음, 행마다 코드·제목·"진행 중 N명". 위에 "사용 중 / 보관" 보기 전환. 선택한 과제는 `?template=<code>`.
- 오른쪽 패널(편집): 제목, 안내문, 종류(안내 / 읽기 / 실습 / 체크리스트 / 평가), 완료 방식(신입이 완료 / 담당자 확인 / 담당자만 처리), 단계, 기한("단계 시작 후 N일"), 해당 없음 허용, 체크리스트 항목(체크리스트일 때), 선행 과제(최대 3개). 아래 "서식" 영역(아래 "서식" 소절), 동작 "저장"·"보관"(보관 보기면 "다시 사용").
- 평가 종류는 교육 담당자에게만 보이고, 고르면 완료 방식이 "담당자만 처리"로 고정된다. 입력 양식 과제(기본 과제)는 종류를 바꿀 수 없다.
- 사용 중인 과제: 제목·안내문 외 칸은 읽기 전용, 패널 위 안내.

| 상황 | 문구 |
|---|---|
| 불러오는 중 | 불러오는 중… |
| 불러오기 실패 | 과제를 불러오지 못했어요. 다시 시도해 주세요. |
| 비어 있음 | 아직 과제가 없어요. "과제 추가"로 첫 과제를 만들어 보세요. |
| 보관 비어 있음 | 보관한 과제가 없어요. |
| 사용 중 잠금 | 신입 N명이 진행 중이라 제목과 안내문만 고칠 수 있어요. 다른 칸을 바꾸려면 보관하고 새로 만들어 주세요. |
| 새 과제 저장 | 과제를 추가했어요. 이후 온보딩을 시작하는 신입부터 들어가요. |
| 저장 | 저장했어요 |
| 저장 실패 | 저장하지 못했어요. 잠시 후 다시 시도해 주세요. |
| 체크리스트 없음 | 체크리스트 항목을 하나 이상 넣어 주세요. |
| 보관 확인 | '제목' 과제를 보관할까요? / 이후 온보딩을 시작하는 신입에게 들어가지 않아요. 진행 중인 신입의 과제는 그대로예요. / 취소 · 보관 |
| 보관함 | 보관했어요 |
| 보관 실패 | 보관하지 못했어요. 잠시 후 다시 시도해 주세요. |
| 다시 사용 | 다시 사용해요. 이후 온보딩을 시작하는 신입부터 들어가요. |
| 다시 사용 실패 | 다시 사용하지 못했어요. 잠시 후 다시 시도해 주세요. |

### 서식

- 자리: 오른쪽 패널의 편집 칸 아래. 저장 전 새 과제는 안내 문구만 보인다. 보관한 과제는 서식 목록(내려받기·지우기)과 안내 문구만 보이고 업로드 영역이 없다. 사용 중 잠금과 관계없이 올리고 지울 수 있다. 한 사람용 과제(S6·S9에서 추가)에 서식을 올리는 화면은 없다.
- 서식 목록·업로드 영역:
  - 파일 행: 형식 아이콘, 이름, 형식·크기·올린 사람·날짜, 내려받기·지우기 아이콘 버튼(마우스를 올리면 툴팁). 순서는 S3와 같다(기본 서식 먼저, 그다음 올린 순서대로).
  - 기본 서식에는 "기본 서식" 배지를 붙이고 지우기 버튼을 두지 않는다.
  - 업로드 영역: 끌어다 놓기 + "파일 선택" 버튼(여러 개 가능). 안내 "docx, xlsx, pdf · 파일당 10MB까지"와 경고 "가상 서식만 올려 주세요. 실명·연락처 같은 개인정보나 실제 사내 문서는 올리지 않아요."
- 기능: 올리기, 내려받기, 지우기(확인 창: "'파일 이름' 서식을 지울까요?" / "이 과제를 받은 신입 모두의 화면에서 사라져요." / 취소 · 지우기). 교체는 지우고 다시 올린다.
- 상태:

| 상황 | 문구 |
|---|---|
| 목록 불러오는 중 | 불러오는 중… |
| 목록 실패 | 서식을 불러오지 못했어요. 다시 시도해 주세요. |
| 서식 없음 | 아직 올린 서식이 없어요. 신입이 작성해야 할 Word·Excel·PDF 양식을 올려 주세요. |
| 끌어 올렸을 때 | 놓으면 바로 올려요 |
| 올리는 중 | 올리는 중 (목록 맨 위 행) |
| 올림 | N개 올렸어요 |
| 올리기 실패 | 올리지 못했어요. 다시 시도해 주세요. (행에 "다시 시도" 버튼) |
| 형식 거절 | '파일 이름' 파일은 올릴 수 없어요. docx, xlsx, pdf 파일만 올릴 수 있어요. |
| 크기 거절 | '파일 이름' 파일이 10MB를 넘어요. 10MB 이하로 줄여서 올려 주세요. |
| 같은 이름 | '파일 이름' 서식이 이미 있어요. 바꾸려면 기존 서식을 지운 뒤 올려 주세요. |
| 지움 | 지웠어요 |
| 지우기 실패 | 지우지 못했어요. 잠시 후 다시 시도해 주세요. (행 아래 표시) |
| 내려받기 실패 | 파일을 내려받지 못했어요. 다시 시도해 주세요. (S3와 같다, 행 아래 표시) |
| 저장 전 새 과제 | 과제를 저장하면 서식을 올릴 수 있어요. |
| 보관된 과제 | 보관한 과제에는 서식을 올릴 수 없어요. |
| 서식 영역 안내 | 올린 서식은 이 과제를 받은 신입 모두에게 보여요. |

## S13. 문제은행 `/team/bank`

- 누가: 교육 담당자(우리 팀 문항만). 메뉴는 "팀 신입 현황 · 시험 출제 · 문제은행 · 온보딩 과제 · 지식 관리".
- 머리말: "우리 팀 시험 문항을 모아 둔 곳이에요. 시험을 만들 때 여기서 먼저 채워요." 오른쪽에 "문항 추가"(주요 동작).
- 필터(목록 패널 머리): 주제 선택(모든 주제 + 게시 문항의 주제, 대소문자·앞뒤 공백 무시), 난이도 칩(전체 / 입문 / 중급), 게시 / 숨김 보기(둘 중 하나).
- 표: 문제(화살표 + 2줄 미리보기), 주제, 난이도, 배점, 출처 배지(시험 / 직접 추가 / 이관 / 기본). 최신순. 좁은 화면에서는 주제·난이도·배점을 문제 아래 한 줄로 옮긴다.
- 행 펼치기: 문제 칸 버튼을 누르면 바로 아래에 편집 상자(문제, 모범 답안, 채점 기준, 주제, 난이도, 배점)가 열린다. 한 번에 한 행만 펼친다. 동작은 "저장"과, 게시 보기면 "숨기기", 숨김 보기면 "다시 게시".
- 문항 추가: 목록 맨 위에 빈 편집 행을 연다. 주제는 고른 주제 필터로 미리 채운다(모든 주제면 빈칸). 동작은 "취소"·"저장". 저장한 문항의 출처는 "직접 추가".
- 결과 자리: "저장했어요"·같은 문제·저장 실패는 편집 상자 아래 줄 왼쪽. 숨기기·다시 게시하면 행이 지금 보기에서 빠지므로 결과는 표 위 알림.
- 주의: 문항은 지우지 않고 숨긴다. 숨긴 문항은 시험 출제(S7)의 "문제은행에서 채우기"에 나오지 않는다. 신입·경영지원·관리자는 들어가지 않는다.

| 상황 | 문구 |
|---|---|
| 불러오는 중 | 불러오는 중… |
| 불러오기 실패 | 문제은행을 불러오지 못했어요. 다시 시도해 주세요. |
| 비어 있음 | 아직 문항이 없어요. 시험을 확정하면 문항이 여기에 쌓여요. |
| 저장함 | 저장했어요 |
| 숨김 | 숨겼어요. 시험 채우기에 더 나오지 않아요. |
| 다시 게시 | 다시 게시했어요 |
| 같은 문제 | 같은 문제가 이미 문제은행에 있어요. |
| 저장 실패 | 저장하지 못했어요. 잠시 후 다시 시도해 주세요. |

- 시안: `docs/design/onboarding-design/screens/S13-bank.html`.

## S14. 규정 문서 `/documents` (2026-11-18 추가)

- 누가: 경영지원 담당자(회사 공통 문서), 교육 담당자(우리 팀 문서). 교육 담당자에게는 회사 공통 문서도 목록에 보이지만 읽기만 한다(지우기·지식 초안 만들기 없음).
- 보이는 것: 페이지 머리 "규정 문서" + 설명 "회사 공통 규정 문서를 올리면 조항으로 나눠 두고, 신입 채팅이 조항을 찾아 출처와 함께 답해요."(교육 담당자는 "우리 팀 문서"), 오른쪽 "문서 올리기"(36, outline). 왼쪽 문서 표(문서 이름 + "형식 · 올린 사람 · 시각", 범위, 상태, 조항 수), 오른쪽 선택한 문서 패널(범위·상태 배지, 문서 이름, 파일 정보, 지우기 아이콘, "지식 초안 만들기"(44, 화면의 주 동작)와 설명, "조항 N개" 목록: 조항 번호·제목 + 본문 두 줄).
- 상태 배지: 처리 중(확인 대기 색) / 사용 중(완료 색) / 처리 실패(보완 요청 색).
- 올리기 창: 제목 "규정 문서 올리기", 설명 "올리면 조항으로 나눠 두고, 신입 채팅이 조항을 근거로 답해요.", "문서 이름"(비어 있거나 파일 이름으로 채운 그대로면 고른 파일 이름으로 채움. 직접 입력·수정한 이름은 파일을 바꿔도 그대로), 범위(역할로 정해져 글자로만 보임), 파일(docx·pdf), 안내 "docx, pdf · 파일당 10MB까지 · 글자가 있는 파일만 읽을 수 있어요(스캔본 제외)", 경고 "가상 문서만 올려 주세요. 실명·연락처 같은 개인정보나 실제 사내 규정은 올리지 않아요.", "취소" / "올리기". 형식·크기 오류는 S12와 같은 문구.
- 처리 중: "문서를 조항으로 나누고 있어요. 1분쯤 걸려요." + 조항 자리 스켈레톤.
- 처리 실패: "글자를 읽을 수 없는 파일이에요. 스캔한 PDF는 읽지 못해요. 글자가 들어 있는 docx나 pdf로 다시 올려 주세요." + "다시 처리" / "지우기". 처리 요청 자체가 실패하면 "문서를 처리하지 못했어요. 잠시 후 다시 시도해 주세요." 문서가 너무 크면(압축을 푼 docx 30MB, pdf 300쪽, 글자 100만 자, 조항 300개 초과) 실패 사유는 "문서가 너무 커요. 나눠서 올려 주세요."
- 지식 초안 만들기: 누르면 "초안 만드는 중…"(비활성). 끝나면 "지식 초안 N개를 만들었어요. 검토하고 게시해야 신입에게 보여요." + 링크 "지식 관리에서 검토하기"(S10 지식 목록, AI 초안 필터. `/knowledge?tab=knowledge&filter=ai`). 이미 있는 질문과 겹쳐 새로 만들 초안이 없으면(0개) 안내(info) "새로 만들 초안이 없어요. 만든 초안은 지식 관리에서 검토해 주세요."와 같은 링크. 실패하면 "초안을 만들지 못했어요. 잠시 후 다시 시도해 주세요."
- 지우기 확인: "'문서 이름'을 지울까요?" / "조항 N개가 함께 지워지고, 채팅은 더 이상 이 문서로 답하지 않아요. 이 문서로 만든 지식은 남아요." / "취소" · "지우기".
- 빈 목록: "아직 올린 규정 문서가 없어요." / "복리후생 규정이나 취업규칙을 올리면 신입 채팅이 조항을 찾아 답해요." + "문서 올리기".
- 올리기 실패: "올리지 못했어요. 다시 시도해 주세요."(창 안에 표시, 입력 유지). 지우기 실패: "지우지 못했어요. 잠시 후 다시 시도해 주세요."
- 원본 파일 내용은 화면에 그리지 않는다. 조항 본문은 텍스트로만 그린다.
- 시안: `docs/design/onboarding-design/screens/S14-documents.html`.
