# 시연 스크립트

`docs/screens.md`의 "시연 흐름"을 단계별 기대 결과와 함께 적은 문서입니다. 스테이징 리허설과 운영 재확인(Task 19 Step 2·5)에 같은 순서로 씁니다.

- 브라우저 창 두 개를 띄웁니다. **창 A**는 신입, **창 B**는 담당자·관리자용이며, 창 B는 시크릿 창으로 열어 세션을 나눕니다.
- 계정 메일은 `docs/judge-guide.md`에 있고, 비밀번호는 별도로 전달합니다. 이 문서에는 비밀번호를 적지 않습니다.
- 시작 전 관리자 화면에서 "데모 데이터 초기화"를 한 번 실행해 시드 상태로 맞춥니다.

## 0. 관리자: 신입 계정 등록

| 순서 | 동작 | 기대 결과 |
|---|---|---|
| 0-1 | 창 B에서 관리자로 로그인 | `/admin/users`로 이동합니다. 상단 바에 "데모 환경 · 가상 데이터"가 보이고, 주 메뉴는 "사용자 관리" 하나입니다 |
| 0-2 | 사용자 표 확인 | 기본 계정 6개는 기본 계정 "예"로 표시되고, 역할 필터에 인원 수가 나옵니다 |
| 0-3 | 역할 "신입", 이름·직급·메일(예: `judge-1@demo.test`)·초기 비밀번호(8자 이상) 입력. 소속 팀은 AI팀, 입사일은 오늘 | "계정 만들기"가 활성화됩니다 |
| 0-4 | "계정 만들기" | 초록 안내 "계정을 만들었어요. 메일과 비밀번호를 전달해 주세요."가 뜨고, 표에 "새로 만듦" 행이 추가되며 기본 계정 값은 "아니요"입니다 |
| 0-5 | 같은 메일로 한 번 더 등록 | 메일 칸 아래에 "이미 등록된 메일이에요"가 표시되고 입력값은 그대로 남습니다 |
| 0-6 | 창 A에서 새 계정으로 로그인 | `/me`가 열리고 진행률이 `0 / 31`로 과제가 준비되어 있습니다 |

## 1. 신입: 타임라인과 명함 신청

| 순서 | 동작 | 기대 결과 |
|---|---|---|
| 1-1 | 창 A에서 신입(`newhire@demo.test`)으로 로그인 | `/me` 타임라인에 입사일·첫 주·첫 달 구간과 "지금 할 일"이 보입니다 |
| 1-2 | 잠긴 과제 확인 | 선행 과제가 남은 과제는 "선행 과제 대기"와 🔒 "○○ 완료 후 열림"으로 표시됩니다 |
| 1-3 | "명함 신청"(GA-07) 열기 → 영문 이름 입력 → 제출 | 자동 채움 미리보기가 보이고, 제출하면 상태가 "확인 대기"가 됩니다 |

## 2. 총무: 명함 확인 → 신입 화면 즉시 반영

| 순서 | 동작 | 기대 결과 |

## 3. 신입: 에이전트 채팅

| 순서 | 동작 | 기대 결과 |
|---|---|---|
| 3-1 | 창 A 오른쪽 채팅에서 "노트북 경비 계정과목이 뭐야?" | 답변이 스트리밍되고 "근거"에 지식 "노트북 경비 계정과목이 뭐야?"가 표시됩니다. 내용은 소모품비(가상 기준)입니다 |
| 3-2 | "동호회 가입비 얼마야?" | 지어내지 않고 "확인되지 않은 내용이에요."로 안내하고, 답변 아래 "담당자에게 등록 요청" 버튼이 보입니다. 이때는 아직 아무것도 기록되지 않습니다 |
| 3-3 | "담당자에게 등록 요청" → 창에 채워진 질문 확인 → "요청 보내기" | 버튼 자리에 "담당자에게 요청했어요" 문구가 남고 미답변 1건이 기록됩니다 |

## 4. 교육 담당자: 미답변에 답 등록 → 신입 재질문

| 순서 | 동작 | 기대 결과 |
|---|---|---|
| 4-1 | 창 B에서 교육 담당자(`trainer@demo.test`)로 로그인 → "지식 관리"(`/knowledge`) | "미답변 질문" 탭에 동호회 가입비를 묻는 질문이 1건 보입니다. 문구는 신입이 요청 창에서 보낸 그대로입니다 |
| 4-2 | "답 등록" → 답변(가상 값)·분류 입력 → "게시" | 미답변이 0건이 되고 지식 목록에 게시 상태로 추가됩니다 |
| 4-3 | 창 A에서 같은 질문 다시 하기 | 방금 등록한 답으로 답변하고, "근거"에 그 지식이 표시됩니다 |

## 5. 교육 담당자: 시험 출제 → 확정·은행 등록 → 인쇄 → 응시 연결 → 결과 기록

| 순서 | 동작 | 기대 결과 |
|---|---|---|
| 5-1 | 창 B `/team` → 신입 상세(S6) | 신입의 과제 진행과 "JS 자습 후 기본기 테스트"(AI-10) 평가 칸이 보입니다 |
| 5-2 | 시험 출제(S7) "새 시험 만들기"에서 주제 "JavaScript 비동기", 난이도 "입문", 문항 수 5 → "문제은행에서 채우기" | "문제은행에 이 주제·난이도 문항이 아직 없어요. AI로 만들어 주세요."가 버튼 아래에 나옵니다(기본 은행에는 "JavaScript 기초"만 있습니다). 은행 채우기는 생성 한도를 쓰지 않습니다 |
| 5-3 | "초안 만들기" | 생성 중 표시가 나온 뒤 문제·모범 답안·채점 기준 초안 5개가 나옵니다. "AI가 만든 답안은 확정 전 검토가 필요합니다" 안내가 함께 보입니다 |
| 5-4 | 문항 카드의 "수정", 또는 "다시 만들기" → (지시 한 줄, 선택) → "새 문항 만들기" | 그 문항만 바뀌고 나머지 문항은 그대로 남습니다 |
| 5-5 | "확정" | 머리 아래에 "확정했어요. 새 문항 5개를 문제은행에 넣었어요."가 나옵니다. 메뉴 "문제은행"(S13)에 이 문항들이 출처 "시험"으로 보입니다 |
| 5-6 | 인쇄(S8) 시험지 / 답안지 | 시험지에는 답안이 없고, 답안지에는 모범 답안·채점 기준이 있습니다 |
| 5-7 | S6 "JS 자습 후 기본기 테스트" 칸의 "응시 시험"에서 방금 확정한 시험 선택 → "연결" | "연결했어요"가 나오고 시험 제목이 목록에 붙습니다(누르면 S8 시험지). 선택지에서는 빠집니다 |
| 5-8 | 같은 칸에서 결과 "통과", 메모 입력 → "저장" | S6 표와 신입 화면(새로고침 없이)의 AI-10이 "완료"로 바뀝니다. 신입은 시험 문제·답안을 볼 수 없습니다. 평가 결과와 메모는 신입 본인에게 보이도록 되어 있습니다(메모 칸 안내 "신입에게도 보여요") |

## 6. 교육 담당자: 두 번째 시험부터 은행 문항이 먼저 채워지고 AI 호출은 부족분만

| 순서 | 동작 | 기대 결과 |
|---|---|---|
| 6-1 | S7 "새 시험 만들기"에서 주제 칸에 `javascript 비동기 `(대소문자·뒤 공백을 다르게), 난이도 "입문", 문항 수 7, 참고할 신입 "선택 안 함" → "문제은행에서 채우기" | 5-5에서 쌓인 5개가 "문제은행" 배지와 함께 붙고, "문제은행에 맞는 문항이 5개뿐이에요. 나머지는 AI로 만들어 주세요."가 나옵니다. 아래 버튼 이름이 "부족분 AI로 만들기"로 바뀝니다 |
| 6-2 | "부족분 AI로 만들기" | 모자란 2개만 만들어 뒤에 붙습니다(생성 한도 1회). 편집기·은행에 있는 문장은 피합니다. 7개가 차면 두 버튼이 모두 비활성입니다 |
| 6-3 | 다시 "새 시험 만들기" → 6-1과 같은 조건에 참고할 신입을 그 신입으로 → "문제은행에서 채우기" | 5-7에서 연결한 시험의 문항은 그 신입이 이미 본 문항이라 빠집니다. 은행의 5개가 모두 빠져 "문제은행에 이 주제·난이도 문항이 아직 없어요. AI로 만들어 주세요."가 나옵니다 |
| 6-4 | 메뉴 "문제은행"(S13) → 주제 "JavaScript 비동기" → 문항 하나 펼쳐 채점 기준을 고치고 "저장" | 행 안에 "저장했어요" |
| 6-5 | 같은 행에서 "숨기기" | 표 위에 "숨겼어요. 시험 채우기에 더 나오지 않아요."가 나오고 행이 빠집니다. S7에서 6-1을 다시 하면 4개만 채워집니다. "숨김" 보기에서 펼쳐 "다시 게시"하면 "다시 게시했어요" |
| 6-6 | "문항 추가" → 이미 있는 문항의 문제를 공백만 바꿔 넣고 나머지 칸을 채워 "저장" | 주제 칸은 고른 주제로 미리 채워져 있고, 저장하면 행 안에 "같은 문제가 이미 문제은행에 있어요."가 나옵니다 |
| 6-7 | 창 A(신입)에서 주소창에 `/team/bank` 입력 | `/me`로 돌아갑니다. 신입 화면에는 문제은행·응시 시험 흔적이 없습니다 |

## 7. 규정 문서: 신입 질문 → 규정 올리기 → 지식 초안 → 규정 원문 → 미답변에서 답 초안

사전 준비: 환경마다 한 번 `docs/deploy.md`의 "규정 문서 시드 색인"을 실행해 "취업규칙 발췌(가상)"을 회사 공통 문서로 올려 둡니다("복리후생 규정(가상)"은 7-2에서 직접 올리므로 `--all`을 쓰지 않습니다). 동호회 가입비와 출장비는 어느 문서에도 없습니다.

| 순서 | 동작 | 기대 결과 |
|---|---|---|
| 7-1 | 창 A(신입) 채팅에서 "야근하면 식대 얼마 받아?" | 규정 문서가 아직 없어 "확인되지 않은 내용이에요."로 안내하고 "담당자에게 등록 요청" 버튼이 보입니다. 누르고 "요청 보내기"까지 보내 미답변 1건을 남깁니다 |
| 7-2 | 창 B에서 경영지원(인사)으로 로그인 → 메뉴 "규정 문서"(S14) | 표에 "취업규칙 발췌(가상)"이 상태 "사용 중"으로 보입니다. "문서 올리기"에서 `supabase/seed-docs/welfare-policy.docx`를 고르고 문서 이름을 "복리후생 규정(가상)"으로 해 "올리기"하면 "올리는 중…" 뒤에 창이 닫히고 상태 "사용 중", 조항 16개가 됩니다(실제 문서와 개인정보는 올리지 않습니다) |
| 7-3 | "복리후생 규정(가상)" 선택 → 오른쪽 패널 | "조항 16개" 목록에 제1조 목적부터 조항 번호·제목·본문 두 줄이 보입니다 |
| 7-4 | "지식 초안 만들기" | "초안 만드는 중…" 뒤에 "지식 초안 N개를 만들었어요. 검토하고 게시해야 신입에게 보여요."와 "지식 관리에서 검토하기" 링크가 나옵니다 |
| 7-5 | 링크로 S10 지식 목록(AI 초안 필터) → 초안 하나 열어 근거 조항·금액 확인 → "게시" | 질문 아래 "AI 작성" 배지가 붙고 게시한 뒤에도 남습니다. 게시하면 "AI 초안" 필터에서 빠집니다. 게시하지 않은 초안은 신입에게 보이지 않습니다 |
| 7-6 | 창 A에서 "결혼하면 경조금 얼마 받아?" | "복리후생 규정 제8조에 따르면…"으로 시작하고 본인 결혼 경조금 50만 원(가상)이 나옵니다. 답변 아래 "규정 원문"에 "복리후생 규정(가상) 제8조 경조금" 칩이 보입니다 |
