# 시연 스크립트

`docs/screens.md`의 "시연 흐름"을 단계별 기대 결과와 함께 적은 문서입니다. 스테이징 리허설과 운영 재확인(Task 19 Step 2·5)에 같은 순서로 씁니다.

- 브라우저 창 두 개를 띄웁니다. **창 A**는 신입, **창 B**는 담당자·관리자용이며, 창 B는 시크릿 창으로 열어 세션을 나눕니다.
- 계정 메일은 `docs/judge-guide.md`에 있고, 비밀번호는 별도로 전달합니다. 이 문서에는 비밀번호를 적지 않습니다.
- 시작 전 관리자 화면에서 "데모 데이터 초기화"를 한 번 실행해 시드 상태로 맞춥니다.

## 0. 관리자: 신입 계정 등록

| 순서 | 동작 | 기대 결과 |
|---|---|---|
| 0-1 | 창 B에서 관리자로 로그인 | `/admin/users`로 이동합니다. 상단 바에 "데모 환경 · 가상 데이터"가 보이고, 주 메뉴는 "사용자 관리" 하나입니다 |
| 0-2 | 사용자 표 확인 | 기본 계정 6개는 기본 계정 "예"로 표시되고, 역할 필터에 인원 수가 나옵니다 |

## 5. 교육 담당자: 시험 출제 → 확정·은행 등록 → 인쇄 → 응시 연결 → 결과 기록

| 순서 | 동작 | 기대 결과 |
|---|---|---|
| 5-1 | 창 B `/team` → 신입 상세(S6) | 신입의 과제 진행과 "JS 자습 후 기본기 테스트"(AI-10) 평가 칸이 보입니다 |
| 5-2 | 시험 출제(S7) "새 시험 만들기"에서 주제 "JavaScript 비동기", 난이도 "입문", 문항 수 5 → "문제은행에서 채우기" | "문제은행에 이 주제·난이도 문항이 아직 없어요. AI로 만들어 주세요."가 버튼 아래에 나옵니다(기본 은행에는 "JavaScript 기초"만 있습니다). 은행 채우기는 생성 한도를 쓰지 않습니다 |
| 5-3 | "초안 만들기" | 생성 중 표시가 나온 뒤 문제·모범 답안·채점 기준 초안 5개가 나옵니다. "AI가 만든 답안은 확정 전 검토가 필요합니다" 안내가 함께 보입니다 |
| 5-4 | 문항 카드의 "수정", 또는 "다시 만들기" → (지시 한 줄, 선택) → "새 문항 만들기" | 그 문항만 바뀌고 나머지 문항은 그대로 남습니다 |
| 5-5 | "확정" | 머리 아래에 "확정했어요. 새 문항 5개를 문제은행에 넣었어요."가 나옵니다. 메뉴 "문제은행"(S13)에 이 문항들이 출처 "시험"으로 보입니다 |
| 5-6 | 인쇄(S8) 시험지 / 답안지 | 시험지에는 답안이 없고, 답안지에는 모범 답안·채점 기준이 있습니다 |
| 5-7 | S6 "JS 자습 후 기본기 테스트" 칸의 "응시 시험"에서 방금 확정한 시험 선택 → "연결" | "연결했어요"가 나오고 시험 제목이 목록에 붙습니다(누르면 S8 시험지). 선택지에서는 빠집니다 |
| 5-8 | 같은 칸에서 결과 "통과", 메모 입력 → "저장" | S6 표와 신입 화면(새로고침 없이)의 AI-10이 "완료"로 바뀝니다. 신입은 시험 문제·답안을 볼 수 없습니다. 평가 결과와 메모는 신입 본인에게 보이도록 되어 있습니다(메모 칸 안내 "신입에게도 보여요") |

## 6. 교육 담당자: 두 번째 시험부터 은행 문항이 먼저 채워지고 AI 호출은 부족분만

| 순서 | 동작 | 기대 결과 |
|---|---|---|
| 6-1 | S7 "새 시험 만들기"에서 주제 칸에 `javascript 비동기 `(대소문자·뒤 공백을 다르게), 난이도 "입문", 문항 수 7, 참고할 신입 "선택 안 함" → "문제은행에서 채우기" | 5-5에서 쌓인 5개가 "문제은행" 배지와 함께 붙고, "문제은행에 맞는 문항이 5개뿐이에요. 나머지는 AI로 만들어 주세요."가 나옵니다. 아래 버튼 이름이 "부족분 AI로 만들기"로 바뀝니다 |
| 6-2 | "부족분 AI로 만들기" | 모자란 2개만 만들어 뒤에 붙습니다(생성 한도 1회). 편집기·은행에 있는 문장은 피합니다. 7개가 차면 두 버튼이 모두 비활성입니다 |
| 6-3 | 다시 "새 시험 만들기" → 6-1과 같은 조건에 참고할 신입을 그 신입으로 → "문제은행에서 채우기" | 5-7에서 연결한 시험의 문항은 그 신입이 이미 본 문항이라 빠집니다. 은행의 5개가 모두 빠져 "문제은행에 이 주제·난이도 문항이 아직 없어요. AI로 만들어 주세요."가 나옵니다 |
| 6-4 | 메뉴 "문제은행"(S13) → 주제 "JavaScript 비동기" → 문항 하나 펼쳐 채점 기준을 고치고 "저장" | 행 안에 "저장했어요" |
| 6-5 | 같은 행에서 "숨기기" | 표 위에 "숨겼어요. 시험 채우기에 더 나오지 않아요."가 나오고 행이 빠집니다. S7에서 6-1을 다시 하면 4개만 채워집니다. "숨김" 보기에서 펼쳐 "다시 게시"하면 "다시 게시했어요" |
| 6-6 | "문항 추가" → 이미 있는 문항의 문제를 공백만 바꿔 넣고 나머지 칸을 채워 "저장" | 주제 칸은 고른 주제로 미리 채워져 있고, 저장하면 행 안에 "같은 문제가 이미 문제은행에 있어요."가 나옵니다 |
| 6-7 | 창 A(신입)에서 주소창에 `/team/bank` 입력 | `/me`로 돌아갑니다. 신입 화면에는 문제은행·응시 시험 흔적이 없습니다 |

## 7. 교육 담당자·인사: 온보딩 과제 관리와 서식

6번까지 끝난 시드 상태에서 시작합니다. 창 B에서 계정을 바꿀 때는 먼저 로그아웃한 뒤 해당 메일로 로그인합니다. 새 과제의 코드는 처음 돌릴 때 `AI-11`이고, 초기화 뒤나 다른 심사위원이 과제를 추가한 뒤에는 번호가 이어집니다(`AI-12`…). 아래 `AI-11`은 그 첫 번째 값입니다.

| 순서 | 동작 | 기대 결과 |
|---|---|---|
| 7-1 | 창 B에서 로그아웃한 뒤 교육 담당자(`trainer@demo.test`)로 로그인 → 메뉴 "온보딩 과제"(`/tasks`) → "과제 추가" → 제목 "사내 위키 둘러보기", 종류 "실습", 단계 "첫 주", 기한 "단계 시작 후 2일", 안내문 입력 → "저장" | "과제를 추가했어요. 이후 온보딩을 시작하는 신입부터 들어가요."가 나오고 첫 주 묶음에 코드 `AI-11`(번호는 위 설명대로 이어질 수 있음)로 보입니다. "진행 중 0명"입니다 |
| 7-2 | 같은 과제의 "서식" 영역에서 "파일 선택"으로 `위키 체크리스트.xlsx`(가상 내용, 10MB 이하)를 올립니다 | "1개 올렸어요"가 나오고 목록에 형식·크기·올린 사람이 보입니다. 저장 전에는 "과제를 저장하면 서식을 올릴 수 있어요."만 보이던 자리입니다 |
| 7-3 | 목록에서 신입이 진행 중인 `AI-09`(BTP 개발 초기 세팅) 선택 → 체크리스트 항목을 고치려 함 | 종류·단계·체크리스트 등은 읽기 전용이고 "신입 N명이 진행 중이라 제목과 안내문만 고칠 수 있어요. 다른 칸을 바꾸려면 보관하고 새로 만들어 주세요."가 나옵니다. 제목만 고쳐 "저장"하면 "저장했어요" |
| 7-4 | 창 B에서 로그아웃한 뒤 관리자(`admin@demo.test`)로 로그인 → "사용자 관리"에서 신입(메일 예: `judge-2@demo.test`. 관리자가 만든 계정은 초기화 뒤에도 남으므로 이미 있으면 다른 메일) 등록(AI팀, 입사일 오늘) → 창 A에서 그 계정으로 로그인 → 접혀 있는 "첫 주" 묶음 머리를 눌러 펼침 | 입사 첫날에는 "입사일" 묶음만 펼쳐져 있습니다. "첫 주"를 펼치면 "사내 위키 둘러보기"가 있고 "서식 1"이 붙어 있습니다. 진행률은 `0 / (31 + 그때 들어가는 새 과제 수)`입니다(새 과제가 `AI-11` 하나뿐이면 `0 / 32`) |
| 7-5 | 창 A에서 그 과제 열기(S3) → "작성할 서식"의 "내려받기" | 안내 바로 아래에 서식 `위키 체크리스트.xlsx` 한 줄이 보이고, 받은 파일 이름이 한글 원본 그대로입니다 |
| 7-6 | 창 B에서 로그아웃한 뒤 교육 담당자(`trainer@demo.test`)로 로그인 → `/team` → 방금 등록한 신입 상세(S6) → "이 신입에게 과제 추가" → 제목 "React 기초 보충 학습", 종류 "실습", 단계 "첫 주"로 "추가" | "추가했어요"가 나오고 목록에 "이 신입만" 배지가 붙습니다. 창 A 신입 화면의 "첫 주" 묶음(7-4에서 펼친 상태)에 새로고침 없이 "할 일"로 나타나고 "지금 할 일" 수가 1 늘어납니다("지금 할 일"은 기한이 이른 5건만 먼저 보여 이 과제는 "나머지 N건 보기" 안에 있습니다). 다른 신입(`newhire@demo.test`)에게는 없습니다 |
| 7-7 | 창 B에서 로그아웃한 뒤 인사 담당자(`hr@demo.test`)로 로그인 → 부서 업무함(`/ops`) → 입사자 필터로 그 신입 선택 → "이 신입에게 과제 추가" | S6과 같은 대화 상자가 열리고 종류에 "평가"가 없습니다. 추가하면 그 신입에게만 들어갑니다 |
